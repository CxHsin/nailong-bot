# 个人 Telegram Agent 首版规格

Status: ready-for-agent

## Problem Statement

用户希望在自己的电脑上运行一个仅供本人使用的 Telegram Agent，用文字自然聊天，并在需要时由模型自行使用网页查询能力。现有仓库尚无应用代码；先前调研包含任务、主动消息、记忆和本机操作等更大范围的构想，不能作为首版要求。用户需要可重启续接、可自行编辑 System prompt、且不会因重置当前对话而丢失旧记录的最小可用版本。

## Solution

提供一个用 TypeScript 和 pi SDK 实现的本地 Telegram Bot。用户手动启动它，Bot 通过 Telegram Bot Token 接收本人账号的私聊文字，使用 DeepSeek 远端 API 生成回复。TinyFish MCP 的网页查询能力以 pi 工具定义提供给模型，由模型按对话需要决定是否调用。Bot 在本地追加保存聊天事件，重启后续接当前对话；`/reset` 追加会话分界事件，使之后的对话从新上下文开始，同时保留旧记录。System prompt 从本地文件读取，重启后应用修改。

## User Stories

1. 作为使用者，我想在自己的电脑上手动启动 Bot，以便控制它何时在线。
2. 作为使用者，我想通过 Telegram 私聊发文字并收到回答，以便日常聊天。
3. 作为使用者，我想让 Bot 只响应我的 Telegram 账号，以便其他人无法使用我的模型额度或读到对话上下文。
4. 作为使用者，我想让 Bot 忽略群聊消息，以便我的私人对话不会进入群组场景。
5. 作为使用者，我想在消息中提供普通网址并询问页面内容，以便不用切换到另一个入口。
6. 作为使用者，我想用自然语言提出需要最新资料的问题，以便模型自行判断是否调用 TinyFish。
7. 作为使用者，我想在不需要查网时直接聊天，以便查询工具不会成为每条消息的必经步骤。
8. 作为使用者，我想看到模型利用查询结果给出的回答，并在引用网页信息时得到来源链接，以便核对信息。
9. 作为使用者，我想让 Bot 使用我的 DeepSeek API 配置，以便由我控制模型调用。
10. 作为使用者，我想让 Bot 使用我的 Telegram Bot Token，以便从我的 Bot 收发消息。
11. 作为使用者，我想让 Bot 使用我的 TinyFish 凭据，以便网页查询能够执行。
12. 作为使用者，我想把凭据留在本地配置中，且不出现在聊天回复或日志中，以便避免意外泄露。
13. 作为使用者，我想让聊天在 Bot 重启后续接，以便不必每次重新交代近期上下文。
14. 作为使用者，我想让完整聊天记录在本地持续追加保存，以便重启和上下文截取不会抹去旧记录。
15. 作为使用者，我想在对话过长时仍能继续聊天，以便模型上下文容量不会阻止使用。
16. 作为使用者，我想发送 `/reset` 开始一段新对话，以便之后的回答不再引用旧对话。
17. 作为使用者，我想让 `/reset` 保留此前的本地记录，以便重置上下文不会删除历史。
18. 作为使用者，我想编辑本地 System prompt 并重启 Bot 后生效，以便调整它的聊天风格与基本指令。
19. 作为使用者，我想在模型、Telegram 或 TinyFish 暂时失败时收到可理解的错误提示，以便知道该消息是否得到回答。
20. 作为使用者，我想在无法联网查询时仍可进行普通聊天，以便查询服务故障不致完全阻断 Bot。
21. 作为使用者，我想在电脑关闭或 Bot 未运行时不收到虚假的完成提示，以便清楚本地运行的边界。
22. 作为使用者，我想首版仅处理文字消息，以便行为范围清晰可预测。

## Implementation Decisions

- 应用使用 TypeScript、Node.js 和 pi SDK。pi 负责 DeepSeek 模型会话及工具调用；应用负责 Telegram 接入、身份限制、配置和本地事件记录。
- 使用 Telegram Bot Token 接入本人账号的私聊文字。启动配置中指定允许的 Telegram 用户 ID；身份与私聊类型在消息进入模型或持久化对话前校验。启动时采用适合本地运行的接收方式，不依赖公网入站服务。
- 远端模型使用 DeepSeek API。模型密钥、Telegram Token、允许的用户 ID 和 TinyFish 凭据由本地配置提供，不写入源码、规格或对话日志。缺少必需配置时，启动给出明确错误。
- TinyFish 通过 MCP 连接。实际可用的 MCP 工具及参数须在实现时验证；仅将完成网页查询所需的工具转换为 pi 工具定义，交给 DeepSeek 自主选择和调用。工具结果返回模型以生成最终答复。若 TinyFish 当前接入未提供足够的网页查询能力，不用未经验证的接口代替，记录为实现阻塞条件。
- 网址作为普通文字输入交给模型。是否查询由模型判断；用户明确提出查询时也不依赖固定关键词或命令。使用网页信息回答时尽可能给出可核对的来源链接。
- pi 的通用本机文件、命令和其他操作工具不对首版模型开放；TinyFish 只暴露与网页查询相关的能力。
- 本地对话记录采用追加式事件序列。记录已接纳的用户消息、Bot 回复以及恢复对话所需的事件；不自动删除旧事件。重启时恢复当前会话。送入模型的历史可按模型上下文容量限制，但持久记录仍完整保留。
- `/reset` 追加会话分界事件。此后的模型上下文从该分界之后构建；此前事件仍可在本地记录中查看。`/reset` 不触发网页查询或普通模型回复。
- System prompt 存在本地可编辑文件中，进程启动时读取；修改后重启生效。每次新会话和恢复会话均使用当前启动时读入的内容。
- 同一私聊的消息按顺序处理，避免并发回复、工具结果和事件追加交错导致续接状态错乱。
- 对外部 API 失败采取可见且可恢复的行为：回复简短错误，不把未生成的回答记成成功；保留已收到的消息，以便诊断或后续继续聊天。
- 现有 TinyFish 接入说明含明文凭据。实现时须把运行凭据转移到不会纳入版本管理的本地配置，避免在命令输出、日志和规格中复制密钥。

## Testing Decisions

- 主要测试边界是 Telegram 更新入口的应用行为。向入口输入模拟的本人或陌生人私聊、群聊、普通文字及 `/reset`；用替身隔离 Telegram 发送、pi/DeepSeek 和 TinyFish MCP；观察回复与本地事件记录。
- 测试外部可见行为，不断言内部函数调用顺序、私有数据结构或 pi 的实现细节。仓库当前无相似测试或既有测试框架可复用。
- 覆盖本人文字消息得到回复；陌生人和群聊不进入模型；模型选择查询时工具结果参与回答；不查询时不要求工具调用；重启后接续；`/reset` 后旧对话不进入新上下文但旧事件仍在；过长记录被截取供模型使用但本地不丢失。
- 对 DeepSeek、Telegram 和 TinyFish 各做一次配置后的人工连通验收，验证真实消息收发、模型回复和至少一次网页查询。自动测试不使用真实密钥或外部额度。

## Out of Scope

- 偏好提炼、长期记忆管理与历史语义检索。
- 本机命令、文件操作、computer use，以及通用插件系统。
- 定时任务、主动消息、提醒、任务卡和后台任务。
- 群聊、多人账号、语音、图片、文件及其他非文字消息。
- 自动开机启动、常驻服务部署、云端托管与电脑关机后的可用性。
- 聊天记录自动清理或通过 Telegram 删除历史记录。

## Further Notes

- 首版的核心验收路径是：本人发送文字并收到 DeepSeek 回复；模型自主使用 TinyFish 回答一个需要查网的问题；停止并重启 Bot 后续聊；执行 `/reset` 后开始新上下文且旧记录仍在。
- 先前产品调研可作为背景，但其中的任务与主动能力不构成本规格的实现要求。
