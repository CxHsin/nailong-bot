# 档案维护与显式图反馈补齐

用户在对照固定上游 Akashic Agent `94027a5cce9fc494f20bb7931fddf26f1e15e8df` 后授权补齐两块能力，分别记录为任务 [#278](https://github.com/CxHsin/nailong-bot/issues/278) 和 [#279](https://github.com/CxHsin/nailong-bot/issues/279)，关联规格 [#268](https://github.com/CxHsin/nailong-bot/issues/268)。档案维护扩展了旧规格保留既有 Markdown 提炼的范围；继续使用 ADR-0012/0015 的数据库、SELF 权威文件和 Durable 事实边界。

## 上游行为与宿主选择

上游 `plugins/markdown_memory/plugin.py` 从完整原对话和当前档案准备草稿，不合格操作允许一次修正；`store.py` 将草稿与来源进度持久保存，再以当前文件和 before-image 检查应用。可重试失败保留进度，后台跟随循环约30秒后继续；定期整理需24小时且5份草稿，超额维护单独执行并以80%容量为目标。上游 `plugins/akasha/learning.py` 读取真实成功 remember/forget 结果，映射经历成员并使用 `remember_boost=3`。

本次在现役 SQLite 保存待办、草稿、前提和回执，以当前条目内容及版本判断冲突，不引入上游的文件工作区宿主。整理按原有条目保留全部来源；容量裁剪使用维护退役标记，保留原文可检索性。保持 SELF 身份保护、冻结快照及明确遗忘的即时失效职责。图反馈从 Durable 保存的调用与结果核对工具名、调用身份、动作及目标，只在有闭合资格时提交。

## 行为验证

新增服务回归通过 `receive`、真实工具调用、最终模型 HTTP 请求、控制状态及 reopen 检查。HTTP 模型和 Embedding 使用受控端点，验证宿主机制，不表示真实模型提炼质量或生产已切换。

- 临时提炼失败持久保留，重开后无新消息恢复，下一请求含提炼结果。旧版本的 terminal `unavailable` 回执、缺失 profile job 也能由配对成功压缩事实恢复，且未重放主请求。恢复测试在接线前实际失败于未恢复，接线后通过。
- 同进程推进30秒后，无新消息会再次尝试失败范围；通过 Magpie 菜单切换模型再重开，后台提炼采用真实已保存选择。无效操作批次修正一次后整体应用，并发写入仍保留，原坏批次没有部分生效。
- 24小时且5份已应用草稿后才整理；合并 MEMORY 的第二来源被遗忘时，下一请求剔除合并正文，另一独立用户原文仍可检索。独立 topic 容量裁剪无需整理资格，保留原文及 SELF。
- 成功显式记住和版本冲突失败调用对后续图补全结果产生不同影响；历史来源可映射既有节点。重复投递及 reopen 保持同一结果。
- 成功工具后回答截断的经历不强化；显式遗忘后切换空间、重开及主动查询仍排除目标。新增反馈字段曾触发模型上下文对整个遗忘回执的遮盖，已调整为保留安全版本、计数及固定确认正文，真实反馈目标保存在 Durable 原件中。

## 集成审查

Standards 只读审查未发现硬规范违反；可选 Duplicated Code 判断为多处读取条目完整来源的表达式重复，未据此确认额外行为缺陷，本轮不扩大为重构。

Spec 初审发现两项需修复：合并 topic 的次来源遗漏于持久自动材料过滤和来源传播；global 与 project 档案维护分别分配完整预算，未计算同请求共现总量。首轮完整测试随修复需要停止，该运行不作为最终验收。另调整既有时钟测试的注入方式：从每次读取消耗数组改为执行间推进固定时间，以允许后台调度读取同一时钟；原来的前缀一致性和新输入时间断言保持。

两项均补了修复前实际失败的服务回归。topic 用例先消费合并档案并保存自动材料，再遗忘第二来源，确认同压缩代后续请求与 reopen 后都剔除合并正文及派生回答；另一个原文仍可检索。材料保存完整来源集合，旧格式从已有来源标签恢复，消费过滤和派生依据传播共用完整集合。容量用例让全局及项目档案各自适合、组合超额，确认维护后主动搜索中的档案已裁剪，两个原文仍可查。维护按同请求可见集合计算 SELF/MEMORY 预算。

Spec 对上述两项修复只读复核后确认均闭合；没有将可选重复代码建议扩大为本轮要求。最终定向记忆和时钟套件19/19通过；显式反馈、学习及图召回定向套件18/18通过。这些结果用于定位各项行为，最终全仓结果另行记录。

完整运行还暴露旧压缩用例未区分后台提炼请求、以及禁止提炼读取已有档案的过时断言。测试端现在独立响应后台请求，只对 `originalSources` 检查会话及用户证据隔离，同时确认 `currentProfiles` 可见共享档案。后台辅助指标也沿用既有回调只报告最终回执的约定，避免 pending 与完成被重复计数；主执行的 batch/request 身份断言保留，独立提炼不伪造主执行 batch。
