# 个人助手触发器扩展讨论

日期：2026-10-17。状态：访谈进行中，仅以下明确列出的范围决定已确认；尚无完整规格或实现承诺。讨论完成并确认后，按 [Issue 约定](../agents/issue-tracker.md)发布结论。

## 已确认的范围

- nailong 继续服务于主人个人。本轮讨论 cron、邮件、主人自己的跨平台私聊，以及这些输入对应的路由与队列行为；具体首批来源及连接器范围待确认。
- 主人自己的 Telegram 私聊和 QQ 私聊应延续同一段对话与工作，支持跨入口理解补充与取消。账号绑定、回复目的地和接入实现尚未确定。
- 群友通过 `@Bot` 获得群内服务属于面向群成员的助手需求，与个人助手增加触发器分开设计。用户最初考虑 NapCat 接入 QQ，暂时只用于一个群；随后确认将群助手移出本轮范围。群会话、旁听、群成员权限及个人记忆可见性均未确认，本轮不据此改变共享记忆设计。
- 附图用于讨论去重、优先级、合批与打扰策略；没有确认采用图中的 Firecracker 或 Temporal。

## 首批用途

- 用户同意定时触发首批支持一次性提醒和周期检查。检查可运行 Agent、使用工具，再根据结果决定是否通知主人；尚未选择具体检查对象。持续跟进到条件满足的目标生命周期不纳入首批。
- 用户同意邮件先作为信息来源，供助手阅读、筛选和发现待办；主人通过私聊继续指挥。没有确认邮件作为主人布置工作的入口，也没有授权自动回复邮件。
- 随后附图分别强调后台任务的打扰策略，以及邮件内容应作为外部资料处理。具体通知条件、执行权限和接入方式仍待讨论；附图的说明不自动成为完整规格。

## 当前基线

- [CONTEXT.md](../../CONTEXT.md)区分 Input Event、Channel、Conversation 和 Queue System。
- [ADR-0011](../adr/0011-durable-main-agent-and-conversation-queue.md)已有直接用户输入高于后台输入、同级 FIFO、已有输入合批和持久执行恢复的设计。
- [ADR-0013](../adr/0013-contextual-input-routing.md)定义现役上下文意图路由；用户补充不依赖已退役的 `/steer` 入口。
- 当前队列已支持同一 Conversation 内的优先级抢占，不能将其描述为跨会话全局抢占或外部工具立即停止。Telegram 当前仅接收主人私聊；cron、邮件和 QQ 尚无现役连接器。

## 待确认

- cron 的创建与管理方式、邮件接入范围，以及后台输入可执行的动作。
- 个人会话与后台执行的关系，主人输入如何关联后台工作。
- 调度定义、事件身份、去重、错过触发和恢复语义。
- 邮件内容与主人指令的区别、输出目的地，以及主动通知的条件。
