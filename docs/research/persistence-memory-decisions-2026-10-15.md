# 持久化工作流与记忆系统讨论

日期：2026-10-15。状态：讨论进行中；下列确认项不是完整规格，也不表示已实现。讨论参考《常驻主动型智能体如何工作》课程笔记第 3、5 章；PDF 位于 `D:/Course/Paper/outputs/常驻主动型智能体/常驻主动型智能体如何工作_notes.pdf`。

后续[队列系统与持久工作流讨论](event-queue-durable-workflow-2026-10-15.md)已确认新的恢复规则：重启后自动恢复，而不是每次等待继续指令；`/reset` 保留事件、执行进度和委派。执行引擎已选定 Pi Durable，见 [ADR-0011](../adr/0011-durable-main-agent-and-conversation-queue.md)。本文件保留此前记忆讨论的原始决策语境，涉及上述行为与选型时以后续确认项为准。记忆系统的其余问题不属于本次队列工作的范围。

## 当前基线

[ADR-0010](../adr/0010-native-pi-assistant.md) 的在线入口使用原生 Pi Session，保存会话、压缩内容和最小帮手观察记录；新数据空间不读取或迁移旧 Akasha。会话持久化与帮手恢复不能作为任意工作流断点续接的保证。当前输入在执行前去重，崩溃可能留下未完成输入。

此前 [Akasha 讨论](akasha-personal-memory-2026-10-12.md) 记录了保留原话、时间和出处、有预算的自动背景召回与主动搜索、不生成稳定偏好档案的方向；它不是当前新入口已经具备的能力。

## 本轮已确认

- 记忆改进优先解决：跨天、压缩或 reset 后，仍能找回讨论经历以及作出决定的原因。
- 重启后先汇报未完成工作、已完成步骤和待核实状态，等待用户决定是否继续；不因重启自行续跑原任务。
- 用户明确希望讨论持久化工作流：得到继续指令后，复用已保存的完成步骤及结果，从中断位置续接，而不只展示一份待办摘要。
- 执行进度按工具操作记录，而非仅记录粗粒度任务阶段。恢复时模型可以重新理解现场，但不能仅因重启就重新执行已完成的工具操作。
- 操作可能已经生效但结果尚未保存时，先核实外部实际状态：确认完成则采用结果，确认未执行才执行，无法确定则说明并等待用户。

以上分别来自用户对第一轮 Q1=A、Q2=B 的回答，以及对第二轮推荐 Q3=B、Q4=B 的同意。经历与决策记忆用于理解历史；工作流状态用于确定执行进度，不能依靠语义召回猜测已完成的操作。

## 待决问题

- 哪些工作进入可恢复工作流，以及工作与普通交流如何区分。
- `/reset` 对已保存记忆与未完成工作的含义；停止、取消与等待续接的关系。
- 经历与决策如何组织、更新、关联原话，以及何时进入当前上下文、何时按需查回。
- 具体操作的完成证据、状态核实方式与无法核实情形的处理。
- 技术选型与验收场景：本轮记忆讨论时尚未选择；后续队列讨论已选定 Pi Durable，完整迁移验收仍待完成。

## 材料的适用边界

课程第 3.5 节展示持久工作流恢复执行进度，但明确恢复进度不等于外部副作用只发生一次；第 5 章区分保存、注入和检索。Profile、Log、Notes 及其数量限制是讲座产品当时的设计示例，不是本项目的既定结构或参数。

本轮是在重新讨论 [规格 #196](https://github.com/CxHsin/nailong-bot/issues/196) 当时暂缓的持久执行与记忆能力。现有原生 Pi 与薄接入方向仍是讨论基线；是否需要改变其职责要由后续决策明确。完整结论确认后按仓库约定发布 GitHub Issue，并在确有架构取舍时记录 ADR。
