# Personal agent 工具融合：真实模型 pilot

2026-10-13，Asia/Shanghai。用户要求开始真实测试，并指定切换为 `gpt-5.6-luna`。任务：[Issue #187](https://github.com/CxHsin/nailong-bot/issues/187)，基于 [#186](https://github.com/CxHsin/nailong-bot/issues/186) 的[隔离实验入口](../../scripts/experiments/tool-surface/README.md)。正式接口和 `.env` 未迁移或修改。

## 结果与判断

**融合接口在这组任务中更容易完成目标，但没有减少全任务用量。** 主试验 20 个任务全部跑完；按目标成果补充复核，独立组 A 为 5/10、融合组 D 为 9/10。预定严格流程检查分别为 3/10、8/10。D 有一次真实委派失败，不能声称全通过。

D 用了 93 次请求，A 为 73 次；累计 input/output/cache token 为 640,555 与 478,516，D 多约 33.9%。这些是整个任务的资源消耗，包含失败尝试；A 有任务较早停止，两组的完成数量也不同，不能只用总量判断完成同一目标的效率。实际费用未取得，不能把 token 数直接换成账单。

结果支持继续试验「基础入口 + skill/CLI，系统处理权限」的方向，尚不足以证明五个工具最优或全面迁移。接口方案同时改变了帮助、当前版本可见性及权限提案方式，不能把差异独立归因于工具数量。

## 主试验设置

- 5 个场景 × 2 个接口 × 2 次独立重复，共 20 个任务。第一轮 A→D，第二轮 D→A；每次重新创建材料、历史、Host 和 Session。
- 模型为 `gpt-5.6-luna`，使用已配置的 `gpt` 端点；仅在测试进程覆盖模型名及 `TOOL_SEARCH=native`。所有已保存模型响应的 `responseModel` 均为该模型名。
- A 使用独立工具；D 使用 read/write/edit/bash/tool_search，文件位置操作、记忆及工作操作经实验技能与 `agentctl`。首次请求 13/5 的计数由此前本地实际 wire 核验支持；本轮未抓取远程 HTTP 工具目录。
- 两组统一每 Session 20 次请求、200,000 token、360 秒模型循环上限；Host 根工作 24 次/全局 30 次调用、全局 300,000 token、执行与续接 360 秒。不重试，请求开始时间跨任务至少间隔 15 秒。
- 使用真实 Pi、Host、文件和持久状态。审批者是固定脚本，只批准工作目录及目标文件，拒绝更宽目录、网络及删除。帮手是确定性合成执行器，未调用真实外部 agent 或 herdr。
- 主试验期间四份模型相关输入未改动，[输入指纹](experiments/tool-surface-luna-inputs-2026-10-13.json)已复核。基准为 `f0d3c50`，后续实验修订与本报告一同提交。

执行命令：

```powershell
$env:MODEL_GPT_MODEL = 'gpt-5.6-luna'
$env:MODEL_GPT_TOOL_SEARCH = 'native'
node --env-file=.env --import tsx scripts/experiments/tool-surface/run.ts --live --model gpt --scenario all --repeat 2 --output C:/Users/Cx/AppData/Local/Temp/nailong-tools-luna-main-v2-20261013.json
```

## 两种验收口径

**预定严格检查**保持原报告的 `checks` 与 `passed`，没有因为结果而回改。它要求历史任务出现 `memory_search` 成功事件，也要求委派结果事件经续接消费。

**目标成果复核是观察结果后的补充分析**，仅放宽两项流程条件：历史已实际读取原消息、答案和角色正确且 Host 完成时，不额外要求搜索调用；帮手文件、子工作和整体工作都完成时，不额外要求结果事件消费。其他条件全部保留，包括拒绝授权时原件不变、正常任务整体结算、实际材料正确及无未知动作派发。

这两项不能混同：A 有一条历史记录已从注入背景取得来源标识并读取原文，无额外搜索；A/D 各有一条委派在同一循环内直接读取成果并结算，`direct_completion` 已消费，后到的 `delegation_result` 被阻断。它们满足目标成果，却未满足预定流程。合成帮手过快、自动记忆背景已有来源标识，使严格指标存在假阴性。

| 场景（每组各 2 次） | A 严格 | D 严格 | A 目标成果 | D 目标成果 |
| --- | ---: | ---: | ---: | ---: |
| 归档 | 0/2 | 2/2 | 0/2 | 2/2 |
| 授权更新 | 0/2 | 2/2 | 0/2 | 2/2 |

## 实际失败与控制事实

- A 两次归档都有正确文件效果，整体未结算；Session 中均出现最新 revision 检查拒绝，随后恢复调用未完成目标。A 第二次历史任务也因结算版本检查失败，原文及答案已正确。
- A 第一次授权请求整个 `protected` 目录，被固定审批者拒绝，文件未改。第二次先提出较宽范围，后来缩小范围获批并成功写入，最终因 revision 检查未完成整体结算。两次都不能只归类为「授权被拒绝」。
- D 第二次委派把帮手放在主 Session 的 `main-*` 内部目录，实际目标工作目录没有 `helper.txt`。子工作已完成、事件已接回，但主工作无法按预期读取材料并完成。工作目录与 Session 目录的事实表达仍需完善。
- 两组四次拒绝授权任务都保持原件；主试验全部 20 次的 `noUnknown` 为真，没有未知或仍派发中的动作。未发现远程 HTTP/预算终止错误；这是本组主模型受控操作的观察，不是对任意 Shell 或真实帮手隔离的证明。
- 远程 Session 中 `tool_search` 调用为 0。端点接受了带客户端搜索声明的请求，本轮没有检验远程专用工具发现、装载或搜索质量。

以上取自[原始主报告](experiments/tool-surface-luna-2026-10-13.json)及[只读 Session/Host 审计](experiments/tool-surface-luna-audit-2026-10-13.json)。审计只保留字段、错误分类和状态；读取原路径不存在时的错误可能是核验动作，不能把全部错误当作误用。

## 预检、脚本修正与证据边界

主试验前的记录全部分开保存，不合并进上述 20 次：

| 阶段 | 结果及处置 |
| --- | --- |
| 原预算、gpt-6.1-sol 归档两组 | A 已操作材料但整个循环 60 秒超时；D 累计 token 达 60,000 上限。不能用作接口胜负。 |
| 切换 luna 的首次归档配对 | A 执行中、D 首请求均收到 HTTP 429；冷却后的低流量探测返回 200，模型名正确。 |
| 180 秒校准配对 | A 版本结算失败；D 12 请求、177 秒通过。完整试验扩大到统一 360 秒。 |
| 第一批完整试验尝试 | 完成 7 次、另 1 次中断后停止：发现 Windows 授权路径大小写比较错误。该批不作为主比较。 |
| 修正后的授权配对 | A 范围过宽被拒绝；D 通过。随后固定入口运行上述主试验。 |

脚本修正包括：Windows 审批路径按 Host 规则归一化；脚本人类结果明确返回给 A；每任务完成即保存不完整报告；历史答案允许角色与原话分行。先读后写授权用例在修正前失败、修正后通过；原固定排版也用分行答案复现了验收假阴性。预算和节流对两组相同。正式运行逻辑未改变。

本机预检 JSON 在 `C:/Users/Cx/AppData/Local/Temp/`：`nailong-tools-live-pilot-20261013.json`、`nailong-tools-luna-pilot-20261013.json`、`nailong-tools-luna-calibrated-pilot-20261013.json`、`nailong-tools-luna-interrupted-20261013.json`、`nailong-tools-luna-approval-check-20261013.json`。中断批次由 stdout 与只读持久状态重建，不具有未保存的节流统计。主报告已归档；临时材料只在运行机器可复核，之后可能被系统清理。

样本仅为五种固定任务各重复两次，审批和帮手均为合成实现，终端为进程内有界适配器。下一轮应先修正工作事实与帮助粒度，再检验来源未注入的历史、真正需要等待的委派，以及计划、取消、浏览器等未覆盖任务。当前先保留生产接口，以实验事实决定后续迁移范围。
