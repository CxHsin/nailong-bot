# Akasha TypeScript 移植、独立 Embedding 与统一模型菜单规格

Based on #267。正式规格为 [Issue #268](https://github.com/CxHsin/nailong-bot/issues/268)；本文为本地归档，不表示功能已实现。

## Problem Statement

用户期望 Akasha 根据语义与经历关联自动找回原始记忆，并使用已配置的 embedding。现役助手虽有逐输入原文召回，但只做词项和中文双字匹配，未接入 embedding 或上游图引擎，同义改述与关联经历的召回不符合预期。单独测通向量接口不能证明实际记忆能力已经存在。

首页分别显示主模型和路由模型，Embedding 缺少入口。本机 Magpie 目录未发现可识别的 Embedding 候选，不能直接复用聊天模型目录。用户需要统一入口管理三种独立选择，查看真实配置、可用状态和历史处理进度，在切换、故障、重启及遗忘后保持一致行为。

## Solution

将固定上游版本的完整 Akasha 核心移植为 TypeScript，接入现役 Assistant Service。用户输入自动触发语义与图联想召回，已完成对话参与学习，保留主动搜索与原文阅读。MEMORY、SELF、主题、默认遗忘、Memory Snapshot 与 Durable Workflow 保持现役职责。

Embedding 使用独立本地服务与模型列表，初始接入已测通的阿里云 text-embedding-v3，后台补齐现役历史。故障时继续聊天并明确降级；切换后新请求使用新模型，在新空间重建向量与图，不混算、不继续调度旧服务。

首页只保留带主模型简写的“模型”按钮，打开后显示主模型、路由模型和 Embedding 模型三项，各自带当前选择简写。思考等级移入主模型页，Embedding 页显示选择、连接、准备进度及测试连接。

## User Stories

1. 作为助手用户，我希望真实输入自动触发原文召回，以便无需先发检索指令。
2. 作为助手用户，我希望换一种说法仍能找回经历，以便不依赖字面重复。
3. 作为助手用户，我希望沿经历关联找回背景，以便获得超出直接向量近邻的相关材料。
4. 作为助手用户，我希望召回保留角色、时间和来源身份，以便核对依据。
5. 作为助手用户，我希望历史材料作为证据注入，以便旧指令不会伪装成当前授权。
6. 作为助手用户，我希望保留主动搜索及分页阅读，以便自动召回不足时继续查证。
7. 作为助手用户，我希望工具全文仍经 Tool Archive 定位，以便不把整份工具日志塞进记忆上下文。
8. 作为助手用户，我希望现有 MEMORY、SELF 和主题保持可用，以便接入不丢失档案。
9. 作为助手用户，我希望同代 Memory Snapshot 稳定且新变更及时追加，以便保持上下文连续性。
10. 作为助手用户，我希望查询结果在工具续步和重启后复用，以便不重复查询或替换已经使用的材料。
11. 作为助手用户，我希望成功零命中与检索失败可区分，以便故障不被解释为没有经历。
12. 作为助手用户，我希望召回遵守项目范围、去重与预算，以便相关材料不挤占当前工作。
13. 作为助手用户，我希望完成的新对话影响未来关联，以便记忆随经历更新。
14. 作为助手用户，我希望中断、暂停和工具续步不被当成完整问答学习，以便关联有真实依据。
15. 作为助手用户，我希望重试、重复输入和恢复不重复学习，以便关联强度不被意外放大。
16. 作为助手用户，我希望纠正后的旧事实不经向量、图或助手改述复活，以便当前表达优先。
17. 作为助手用户，我希望忘记立即影响召回、快照与摘要，以便缓存和后台任务不恢复排除资料。
18. 作为助手用户，我希望默认遗忘保留原始记录，以便它不会变成未经请求的物理删除。
19. 作为助手用户，我希望后台补齐现役历史向量，以便接入前经历也能被语义检索。
20. 作为助手用户，我希望补齐期间继续聊天和处理新输入，以便不等待全量准备完成。
21. 作为助手用户，我希望只有完整证据的历史轮次参与图学习，以便不编造轮次与过去反馈。
22. 作为助手用户，我希望无法证明完整轮次的有效原文仍可检索，以便资格不足不等于历史丢失。
23. 作为助手用户，我希望重启继续准备且复用已有向量，以便避免重复成本。
24. 作为助手用户，我希望看到真实准备进度与失败原因，以便知道能力是否就绪。
25. 作为助手用户，我希望退役旧 Host 数据保持退役，以便新引擎不重新导入旧命名空间。
26. 作为助手用户，我希望本地配置独立 Embedding 服务与模型，以便不受 Magpie 目录限制。
27. 作为助手用户，我希望首次使用已有阿里云配置，以便无需重复录入可用连接。
28. 作为助手用户，我希望本地添加配置后在 Telegram 选择，以便换服务无需修改功能代码。
29. 作为助手用户，我希望凭据只在本机管理，以便 Telegram、日志和错误信息不泄漏 API Key。
30. 作为助手用户，我希望 Embedding 选择服务级生效并跨重启保留，以便共享记忆一致。
31. 作为助手用户，我希望区分已选择与连接可用，以便保存成功不被当成请求成功。
32. 作为助手用户，我希望连接测试返回耗时、有效维度或安全失败原因，以便判断配置。
33. 作为助手用户，我希望连接测试使用合成文本，以便不产生假用户记忆或发送历史。
34. 作为助手用户，我希望未配置、认证失败或超时时仍可聊天，以便记忆故障不拖垮助手。
35. 作为助手用户，我希望远程等待有上限，以便单次查询不无限阻塞。
36. 作为助手用户，我希望恢复后后台自动继续，以便不靠下一次查询唤醒。
37. 作为助手用户，我希望切换后新调用使用新模型，以便不产生未预期的旧服务用量。
38. 作为助手用户，我希望不同 Embedding Space 严格隔离，以便同维度也不会误混算。
39. 作为助手用户，我希望换 Embedding 保留原始资料和档案，以便重建只影响派生状态。
40. 作为助手用户，我希望换主模型或路由模型不重建记忆，以便三种选择独立。
41. 作为 Telegram 用户，我希望首页只显示一个带主模型简写的模型入口，以便减少分散按钮。
42. 作为 Telegram 用户，我希望子菜单有三种模型入口，以便分别管理其职责。
43. 作为 Telegram 用户，我希望三个入口显示当前选择，以便无需逐页检查。
44. 作为 Telegram 用户，我希望主模型与路由沿用 Magpie 列表、分页和收藏，以便保留熟悉操作。
45. 作为 Telegram 用户，我希望主模型页包含思考等级，以便生成设置集中。
46. 作为 Telegram 用户，我希望 Embedding 页显示独立配置及准备进度，以便不误认为来自 Magpie。
47. 作为 Telegram 用户，我希望 /model 无参数打开三项菜单且保留带 ID 的旧用法，以便快捷操作继续可用。
48. 作为 Telegram 用户，我希望简写不改变完整身份，以便同名模型不会误选。
49. 作为 Telegram 用户，我希望忙时也能查看和设置模型，以便无需等整个 Processing Turn。
50. 作为 Telegram 用户，我希望设置不自动恢复 Paused Work 或重放工具，以便换模型不构成继续授权。
51. 作为助手用户，我希望 reset 保留模型选择、准备状态和遗忘，以便重置上下文不清空记忆配置。
52. 作为维护者，我希望移植有固定上游输入输出对照，以便验收有实际证据。
53. 作为维护者，我希望生产运行不依赖 Python 工作进程，以便由现有 Node 服务承载。
54. 作为维护者，我希望真实接口、受控测试、手机观察和部署状态分别记录，以便明确证据范围。

## Implementation Decisions

1. **固定核心与许可。** TypeScript Akasha Engine 对照上游 94027a5cce9fc494f20bb7931fddf26f1e15e8df，覆盖 dense/BM25、时间与上下文证据、图关联和时序学习、扩散、衰减、激活、抑制及读出，保留 MIT 版权许可。不新增生成式 LLM 作为检索和图学习评判器；既有 Markdown 提炼保持职责。
2. **行为等价。** 保持上游中文搜索分词及词频、UTF-8 字节词序、稳定排序和并列节点优先级，不用双字或 locale 顺序冒充。保留 float32/float64 运算边界，公开数值容差，不以容差掩盖排名、离散拓扑和来源身份差异。不承诺跨环境逐位相同。
3. **宿主适配。** 扩展现有输入准备、响应与处理结束流程，自动 Akasha Recall 与主动 memory_search 使用同一服务拥有的引擎和过滤契约。Assistant Service 负责身份、顺序、配置与生命周期；Engine 不替代档案、快照或 Durable 执行事实。
4. **本地配置列表。** 独立 Embedding 列表提供稳定配置 ID、显示名称、OpenAI 兼容基础地址、模型 ID、API Key 的本地环境引用及超时/输入切片限制，沿用现有本地配置加载约定。凭据不进入 Telegram、模型上下文或一般日志。配置错误显示不可用，不清除资料或阻止普通聊天。
5. **现有环境接入。** 未配置独立列表且 EMBEDDING_BASE_URL、EMBEDDING_MODEL、EMBEDDING_API_KEY 齐全时形成初始项；沿用 EMBEDDING_TIMEOUT_MS、EMBEDDING_MAX_INPUT_CHARS，缺省为 3000 毫秒和 6000 Unicode code point。首次无已保存选择才采用合法初始项；显式列表优先，不反复覆盖用户选择。
6. **持久选择。** 配置由本机管理，选中稳定 ID 服务级持久保存。刷新、reset、重启不得重置选择；选中项被删或无效时显示原选择不可用，不静默切换服务。主模型仍按 Conversation，路由仍按服务保存。
7. **请求有效性。** 调用选中服务的兼容 embeddings 接口。长文按连续 code point 分片并以固定规则合成向量，不改写来源。验证条数、顺序、非空、有限数值、非零及一致维度后提交缓存/学习；非法响应按故障处理。缓存区分原文指纹和空间身份。
8. **Embedding Space。** 身份区分服务、模型及可用版本、预处理/分词版本、实际维度和归一化规则，同维度不表示兼容。检测变化后在新空间重建并显示状态，不混用旧向量或图，不公开秘密。
9. **切换边界。** 每次记忆请求冻结配置与空间；在途请求可按原配置收尾，切换后新请求及后台批次不再调度旧服务。迟到旧结果不得写入新空间。主模型、路由的请求冻结及暂停契约继续保留。
10. **后台准备。** 以有界批次/并发、超时、取消和退避补历史并持续处理新输入，持久保存消费位置和已提交结果。重启继续且不重复已完成工作。不等待全库完成才聊天；不足时使用当前可用结果与本地检索，公开实际进度，不把半成品发布成完整基线。
11. **历史学习资格。** 只索引现役有效来源，保留角色、项目、Conversation、父来源和真实时间含义。结合 Queue 与 Durable 核对输入关联、已提交响应和处理结束，不直接把来源行、toolUse/length、暂停或目标完成措辞当成闭合问答。无法证明资格的有效原文仍可检索，保留不学习原因。
12. **真实学习事实。** 新对话保存输入/响应身份、顺序、实际结束、当次查询出处和真实反馈；闭合后按固定顺序学习。合批和补充不强行改为一对一。历史不补造旧召回、反馈、结束时间或送达成功；Processing Turn 结束不等于用户目标完成。
13. **幂等和存储。** 来源、向量、学习样本、消费位置使用稳定身份，重试、重复输入、恢复不重复学习。派生向量与图归现役记忆空间，按原文与合法学习输入恢复，不改写 Durable 结果，不建立另一套 Task 或权限系统。具体表结构由实现选择，但必须保留空间、出处和恢复所需事实。
14. **自动结果复用。** 保持输入身份、范围、去重、预算与历史材料标记。成功结果包括零命中持久复用；实际使用的降级材料也保存出处和原因，不标为成功语义零命中，不在同一输入工具续步偷偷替换。恢复后的新输入和主动查询可使用恢复能力。
15. **遗忘与纠正。** 在候选、向量、图输出、主动读取、后台提交和实际注入边界核对排除来源及派生关系。旧空间、待完成批次、reset 和重启不能复活排除资料。继续使受影响快照与压缩摘要失效；默认遗忘不物理删除原文。
16. **故障与关闭。** 区分未配置、配置错误、401、超时、断网和非法向量，安全显示降级。前台远程等待受配置整体上限约束；后台恢复不依赖新消息，不忙循环重试。关闭停止新任务、取消或排空在途任务后释放资源，重启从已提交位置继续。
17. **现有控制边界扩展。** 在现有 controlSnapshot/control 中增加脱敏 Embedding 选择、可用性、准备进度、测试结果及对应选择/测试操作，复用认证、操作去重与持久状态。测试固定合成文本，返回结果、耗时和有效维度；不写用户来源、图学习、队列目标，不触发主模型生成。只查看页面不发测试请求。
18. **模型菜单。** 首页移除独立路由与思考等级行，保留一个模型入口。子菜单三项附当前简写及返回导航；主模型页保留列表、分页、详情、收藏和思考等级，路由复用原目录，Embedding 仅列本地配置并提供状态/进度/测试。简写优先可读显示名，否则取模型 ID 最后段，详情保留完整身份；回调绑定稳定 ID，不按简写定位。
19. **命令与在途工作。** /model 无参数进入三项菜单，带完整 ID 保留主模型切换；/thinking 仍可直达思考设置。选模型与测试连接不等待整个 Processing Turn、不自动恢复 Paused Work、不重放已确认步骤。保留既有 owner/chat/message 校验、过期按钮处理和重复操作契约。
20. **配置生效与交付。** 已确认设计调整 ADR-0012 的字面实现选择，并扩展 ADR-0016 的菜单；ADR-0017 为新方向。保留原始资料、现役 namespace 和服务设置，不恢复退役数据。代码、构建、实际请求、进程是否切换及真实手机观察分别记录；提交和构建不代表部署完成。

## Testing Decisions

1. **已确认的最高入口。** 以现役 Assistant Service 的 receive、controlSnapshot/control、实际发送给模型的请求材料及 reopen 为主要验证边界，叠加原生 Telegram 更新/回调入口。用户已在设计轮次确认服务与面板组合验收，不另造测试专用业务流程。
2. **现有先例。** 复用服务记忆及遗忘测试的临时真实 SQLite、受控聊天 HTTP 与重启夹具；复用控制面板、模型控制和路由测试的 Magpie 目录、Telegram 更新及请求冻结夹具。新增独立受控 embedding HTTP 行为，观察实际输入、模型 ID、调用次数与响应，不用假的内部成功标志代替服务接线。
3. **算法对照边界。** 用固定原文、词频、Turn、向量、时间和反馈运行原 Python 核心生成结果，驱动 TypeScript 相同外部序列。比较分词、逐步学习状态、查询票据、排名、图拓扑、来源及恢复结果。数值容差与固定版本随夹具公开；临界阈值/并列和 float32 路径须有案例，容差不可豁免错误节点、排序、学习资格。Python 仅用于开发验证，不成为生产工作进程。
4. **召回与注入。** 通过真实输入验证无共同字面词的改述能召回预先标注原文、关联召回能超出直接近邻，并检查最终 wire 材料而非只查数据库。覆盖主动搜索、来源角色/时间、证据标记、项目范围、预算、去重、空结果和同输入续步/reopen 复用。
5. **历史与在线学习。** 以受控现役历史同时包含闭合轮次、暂停、中断、工具续步、合批和关联不足资料，验证有效原文可检索，只有合资格样本学习且顺序可核查，不生成虚假反馈/时间。新对话闭合后改变未来关联；重复输入、恢复和后台重试不重复学习。处理时继续接受新消息，进度来自真实提交数。
6. **空间切换。** 使用同维度不同语义的两个服务及维度变化案例，验证新调用只用新选择、不混算旧图/缓存、旧在途结果不会污染新空间，历史可恢复重建、原文不变。主模型/路由切换不得增加 embedding 重建调用；多个 Conversation 共享 Embedding 选择。
7. **故障与恢复。** 覆盖未配置、坏配置、401、超时、断网、空/非有限/全零/维度或条数错误响应，检查聊天继续、等待受限、状态区分、失败不伪装零命中、无秘密泄漏。修复服务且不发送新查询时后台仍恢复，关闭后无遗留 worker 请求，reopen 继续已提交进度。
8. **遗忘与缓存竞态。** 同时覆盖原话、助手改述、图关联、后台向量任务、旧模型空间、快照及摘要；遗忘/纠正后在当前请求消费、reset 与 reopen 均不恢复失效材料。保留原始资料和无关工作事实。
9. **原生菜单。** 以 Telegram 消息和按钮验证首页单入口、三项当前简写、列表及返回、思考等级位置、独立配置选择、测试反馈与进度。验证同名简写仍操作正确 ID，/model 两种用法、/thinking、忙时即时应答、过期/重复/错误用户回调与重启。查看和选择不发聊天生成，连接测试只发合成 embedding 且不写记忆，不恢复暂停工作。
10. **真实接入验收。** 用当前有效配置和独立临时现役数据空间，经正式环境组合入口生成真实向量并进行跨措辞召回、状态查询和重启。记录模型、维度、耗时、最终注入证据及实际条数，不记录凭据或私人正文。受控算法案例不当作真实 embedding 效果证明；本次已授权的 embedding 用量不等于授权生产 Telegram 发信或重启，手机观察与生产切换未做时明确记为待验收。
11. **完成检查。** 运行类型检查、完整项目测试、构建和文档链接检查，记录实际用例数及修复前失败的回归；额外真实调用仅为覆盖未证实行为。交付实际结果与局限，不以 Issue/ADR 状态或单条 embedding HTTP 200 宣称集成完成。

## Out of Scope

- 恢复或导入已退役旧 Host、旧 Akasha 数据、旧离线入口及已删备份。
- 将整个上游 Agent、插件宿主、Ledger、UI、主动行为或调度框架搬入本项目。
- 生产 Python 工作进程或仅以简单向量排序替代完整移植。
- 为 Magpie 新增 Embedding 能力、修改/自编译 Magpie 或迁移主模型、路由到独立直连。
- 重写 MEMORY/SELF 人设规则、Markdown 提炼、Durable 执行事实、权限与队列体系。
- 将所有工具全文、helper 声称或未闭合输出当成完整用户问答学习。
- 物理删除原始记忆、自动清理旧空间或静默丢弃未知历史。
- 未获明确授权的 Git 推送、PR 合并、生产重启与 Telegram 外部发送。
- 保证任意中文、任意用户的检索质量或任意硬件下固定性能；不以合成向量评估替代真实模型效果。
