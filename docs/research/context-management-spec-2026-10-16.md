# 稳定上下文、工具结果分页归档与分层记忆规格

Based on #207

日期：2026-10-16。状态：待实现规格；用户已确认设计方向及主验收边界。权威规格为 [Issue #208](https://github.com/CxHsin/nailong-bot/issues/208)，标记 `ready-for-agent`。本规格扩展 #201 的上下文与记忆范围，不改变现有 Queue System、Durable Workflow 和 Delegation 的职责。

## Problem Statement

常驻 Personal Agent 的对话、工具输出与资料不断增长，主模型容易被大量中间材料占满。反复改写 system 材料、重新组装记忆或回灌旧工具全文会破坏可复用前缀。只截断输出又会丢失证据，压缩后若连引用都不在摘要中，助手便不知道如何找回以前的执行结果。

用户还希望跨天、压缩、reset 和进程重启后保留个人偏好、关系理解、经历与决策原因，同时能够纠正和忘记。当前生产入口使用 Pi Durable 1.2.0，旧 Host 的 Akasha 与上下文投影不在生产路径，不能把历史实现当成已具备的能力。执行是否完成必须继续依据 Durable 的实际记录，不能依靠记忆或摘要猜测。

## Solution

建立稳定的活动上下文与独立的长期记忆：尽量复用已发送前缀，把新材料追加到当前输入；长工具结果首次返回即保存为持久原件，主上下文只接收受限视图和来源。旧结果可通过固定归档检索入口重新定位，再按需分页读取。

长期记忆采用常驻 Markdown 档案、主题自动浮现与 Akasha 原文召回，保留主动搜索和原文阅读。system 记忆快照固定到下一次压缩或 reset，重启复用实际快照；新记忆和纠正立即通过追加材料生效，遗忘则立即使受影响派生内容失效。会产生大量中间材料的独立子任务委派给 helper，主助手保留整体目标、决策和必要结果。压缩沿用原生机制，保留近期对话原文和可继续工作的摘要。

## User Stories

1. 作为用户，我希望稳定工具定义与 system 材料保持顺序，以便连续对话能复用已有输入前缀。
2. 作为用户，我希望新历史和动态材料追加进入上下文，以便不会每轮重写已发送内容。
3. 作为用户，我希望工具续步沿用既有结果视图，以便同一输出不会反复变形或重新灌入全文。
4. 作为用户，我希望 system 记忆快照在同一压缩代内固定，以便记忆读取不会不断破坏前缀。
5. 作为用户，我希望重启复用实际保存的快照，以便重启不会悄悄改变同代 system 内容。
6. 作为用户，我希望新增记忆和纠正即时进入当前上下文，以便不用等压缩后才能影响回答。
7. 作为维护者，我希望观察真实请求、缓存 usage 和延迟，以便分清前缀稳定与远端缓存命中。
8. 作为用户，我希望过长工具结果首次返回时即被卸载，以便主上下文不先承受完整输出。
9. 作为用户，我希望受限视图保留成功、失败、关键错误及来源，以便助手仍能判断下一步。
10. 作为用户，我希望完整工具结果持久保存，以便压缩或重启后仍可核查证据。
11. 作为用户，我希望每次回读同时限制行数和字节数，以便分页不会成为另一种全文回灌。
12. 作为用户，我希望超长单行也能继续分段读取，以便大 JSON 或压缩日志不会卡在同一位置。
13. 作为用户，我希望助手只读取相关页面，以便不自动遍历所有归档内容。
14. 作为用户，我希望已知引用可以直接读取，以便不必每次先搜索。
15. 作为用户，我希望引用不在摘要中时也有固定检索入口，以便仍能发现过去的工具结果。
16. 作为用户，我希望按关键词、时间、工具、命令和关联文件筛选，以便区分相似的历史执行。
17. 作为用户，我希望搜索本身只返回有限条目和继续位置，以便归档索引也不会占满上下文。
18. 作为用户，我希望能区分修复前失败与修复后成功的测试日志，以便不会误用旧证据。
19. 作为用户，我希望图片和资源保持类型并保存来源，以便图片 base64 不被当作普通文本塞入上下文。
20. 作为用户，我希望主助手把高上下文成本的独立工作交给 helper，以便保留对整体任务的理解。
21. 作为用户，我希望同一子任务复用同一 helper 上下文，以便不反复交接和丢失局部进度。
22. 作为用户，我希望 helper 返回简洁结论和必要来源，以便主助手按需核查详细材料。
23. 作为用户，我希望轻量任务仍可直接处理，以便不会为简单工作付出额外委派开销。
24. 作为用户，我希望视觉任务委派能使用实际可访问的图片与会话，以便不会假定 helper 继承了登录状态。
25. 作为用户，我希望长期保留有原话依据的偏好和要求，以便跨会话不必重复说明。
26. 作为用户，我希望助手可以维护对我的理解与关系定义，以便相处连续且能随我的表达更新。
27. 作为用户，我希望全局及项目主题能自动浮现，以便当前问题得到相关背景。
28. 作为用户，我希望 Akasha 根据当前真实用户输入召回原始经历，以便检索不依赖先拼装 Markdown。
29. 作为用户，我希望不同记忆通道分别受限并去重，以便同一事实不会多次占用输入。
30. 作为用户，我希望仍能主动搜索和阅读原文，以便自动召回不足时继续查证。
31. 作为用户，我希望一次输入的检索结果在工具续步和重启后复用，以便不会重复查询或改变已注入材料。
32. 作为用户，我希望没有命中也被记录，以便工具续步不会反复执行空检索。
33. 作为用户，我希望压缩后的后台提炼依据原始对话，以便有损摘要不会被当作用户证据。
34. 作为用户，我希望明确要求记住或纠正时立即更新，以便当前表达优先于旧画像。
35. 作为用户，我希望画像变更能追到原话和替代关系，以便知道某个判断从哪里来。
36. 作为用户，我希望 helper 只提交记忆候选，由主助手统一写入，以便共享记忆不会被多方直接覆盖。
37. 作为用户，我希望默认忘记会删除对应画像并阻止相关来源自动召回，以便旧判断不再自动影响回答。
38. 作为用户，我希望遗忘立即清除受影响快照与摘要中的派生内容，以便缓存不会延迟遗忘生效。
39. 作为用户，我希望遗忘规则跨 reset 和重启保留，以便后台提炼不会重新学回已经忘记的内容。
40. 作为用户，我希望压缩保留近期原文、目标、约束、决策原因、进度和下一步，以便助手能继续工作。
41. 作为用户，我希望压缩保留必要来源而无需逐工具清单，以便能找回证据又控制摘要成本。
42. 作为用户，我希望恢复时依据 Durable 判断实际执行情况，以便摘要中的“完成”不会导致重复操作或遗漏未知效果。
43. 作为用户，我希望 reset 保留队列、执行进度、委派和长期记忆，以便清理主上下文不等于取消工作或遗忘。
44. 作为维护者，我希望分别测量主上下文收益与全链路调用成本，以便委派、压缩和缓存的效果有实际依据。

## Implementation Decisions

### 1. 职责与接入边界

- Assistant Service 负责输入身份、材料准备、归档入口和 helper 材料交接；Pi Durable 保持模型与工具执行、原生压缩和已确认结果恢复的职责。记忆是供模型理解的材料，不能决定操作是否已执行。
- 新能力接入当前生产数据空间。历史 Host、旧 Akasha 和旧上下文投影仅供参考，不为启用新记忆而自动导入旧命名空间。
- 复用现有 Queue System、Input Event、Input Batch、Explicit Steering、Helper Observation 与恢复协议；不增加平行的通用 Task 状态机或执行账本。

### 2. 输入顺序、快照与缓存

- 在 provider 和 SDK 的消息约束内固定工具定义及 system 段落的确定性顺序：基础人设与行为规则、项目及技能材料、常驻记忆快照。SDK 有固定 instructions 位置时遵守其协议，不通过绕过编码器换取表面顺序。首次接入须记录实际编码后的布局。
- system 之后保留当前压缩摘要与近期历史的原有顺序；新用户输入保持原文、身份和消息边界，相关主题召回、Akasha 结果、记忆变更与 helper 返回作为有来源的动态材料在对应输入边界追加。工具输出、旧资料与 helper 返回不能伪装成当前用户指令。
- 本轮不按每次问题裁剪工具 schema，不为了缓存反复改写旧工具结果，也不把每次动态检索塞回 system。真实项目指令或工具配置发生变化可以使相应前缀更新，不能为了缓存继续沿用过期指令。
- 以 Conversation、Session 与压缩代定位记忆快照，保存实际内容及其来源版本。重启恢复相同内容，而非从最新 Markdown 重新组装并称其为同一快照。压缩或 reset 开启新快照；已完成的检索与追加材料有持久身份，恢复不重复注入。
- 同代新增记忆和纠正即时追加，并明确旧事实已被替代；下代再归并到快照。遗忘是强制失效例外，受影响快照、摘要和自动召回材料立即重建或排除，不能等常规压缩。
- 记录实际请求的输入规模、provider 提供的 cache read/write、请求延迟和模型信息。provider 未提供的指标标为不可得；前缀相同不等于远端命中。当前价格为零时不能据其 cost 字段宣称省钱。

### 3. 长工具结果首次卸载

- 统一覆盖会进入主模型上下文的原生工具、连接器最终结果和进度材料。对可持续增长的进度做增量受限视图，不能靠多次小进度绕过总量约束；最终结果与执行事实仍由 Durable 保存。
- 工具结束后、完整内容进入主模型前，过长结果保存为持久原件，并生成确定性的受限视图。视图说明内容已卸载，保留足够的状态、错误或退出码，以及稳定来源与分页入口。恢复沿用已保存视图，不重新随机选片段。
- 原件和索引属于持久数据，不只放在可随时清理的临时目录。至少在 Conversation 与其 Durable 数据保留期间可访问；本轮不新增自动过期删除。缓存视图可重建，原始证据不可因压缩或 reset 被当作缓存清掉。
- 先复用现有 read 的文件、行位置和数量能力。文本回读具有行数与字节双上限；响应提供实际覆盖范围、是否还有内容及下一位置。超长单行须支持字节或分段游标推进，或者提供保持原文映射的有界读取视图，不能只重复提示该行超限。实现选用最小兼容扩展，不宣称现有 read 已支持尚不存在的游标。
- 搜索与读取均使用有限默认值和硬上限；过大的请求仍被上限约束。读一页不自动预取或遍历后续页。全文在存储中保留，模型仅按当前问题选择需要的页。
- 阈值、预览预算和页预算须可配置，交付时列出默认值与选择依据；不能将课程参数直接视为最优值。必要状态和引用必须位于原生压缩可见的受限部分，避免被工具文本截取规则裁掉。
- 原件写入失败时返回明确的归档失败和可用的受限信息，不提供虚假的可读引用，不把失败伪装成工具执行失败而自动重跑有外部效果的操作。已执行事实仍按现有 Durable 与未知效果协议处理。

### 4. 旧归档的发现与分页读取

- 提供可从稳定工具说明中发现的归档检索入口，说明“已知引用直接读，未知引用先搜索”。无需把完整历史索引注入每轮 prompt。
- 搜索复用 Durable 的调用身份、时间、工具名、可用的命令或参数摘要、状态、关联输入与文件，并附上归档引用。元数据由程序从已有记录生成；任务关键词使用已有输入或任务关联，不额外调用模型逐条生成标签，不复制另一份完整执行流水。
- 在当前 Conversation 的记录内按关键词及可用的时间、工具、命令、关联文件筛选。搜索结果返回有限候选，每条含可区分执行的时间、状态、简短匹配信息、稳定引用和读取入口，并返回下一页位置。查询范围和截断情况必须可见。
- 搜索负责定位，不自动读出候选全文；选中候选后再分页读原件。索引和引用跨压缩、reset 与重启有效；摘要没有保留某个引用时也能搜索。无匹配、索引不可用和原件缺失分别说明，不能都当成“从未执行”。
- 例如查询以前的 npm test 记录，应能分辨修复前失败和修复后成功，按需读取失败原因或最终统计。工具日志不整批放进 Akasha，语义记忆不替代归档检索。

### 5. 高上下文成本任务委派与媒体

- 按任务独立性及预期中间材料量决定委派。连续截图、批量图片、长资料阅读和大型调研均可适用；不限定视觉，不要求轻量工作都派发 helper，也不承诺委派一定降低总费用。
- 复用 herdr-workflow、herdr_watch、内部返回队列与真实身份恢复。同一子任务尽量复用同一 helper；重启查询原身份，不盲目重派。主助手继续持有整体目标、约束、决策与结果验收责任。
- 交接包含子任务目标、必要输入位置和所需成果。helper 返回简洁结论、未解决问题与必要证据引用；大报告、日志和中间资料留在文件中。主助手按需读相关片段，不自动回填全部中间上下文。
- MCP 接入保留 text、image、资源引用等类型，不能把图片 base64 JSON 化为主模型文本。媒体原件落文件，使用包含来源与顺序的 manifest 交接，helper 用其自身读取能力查看；不为此另建图片传输协议。
- 批量高成本媒体的路由应发生在完整媒体送入主模型之前；用户直接给出的简单图片仍可由主助手处理，不能因统一文本卸载而丢失必要视觉能力。
- 使用现有登录页面前核对 helper 能否连接对应 tab 或会话；确实不能连接时说明限制，依据可用材料继续，不能报告未执行的浏览操作。主助手必要时可读取选定图片和证据。

### 6. 三路记忆与检索生命周期

- 常驻 Markdown 档案区分 MEMORY、SELF 和全局/项目 topics。MEMORY 保存用户事实、偏好及明确的长期要求；SELF 保存有依据的用户理解和关系定义，奶龙基础人设继续由 system prompt 定义。
- 常驻档案、主题自动浮现、Akasha 原文召回分别设有限预算，并在合并时按来源和事实去重。保留显式记忆搜索与原文读取；超出预算时提供定位信息，不能把全库拼到 prompt。
- Markdown 快照准备与 Akasha 查询彼此独立；Akasha 使用当前真实用户输入，不以已拼装 Markdown、助手摘要或工具输出作为用户查询。主题浮现也保留所对应的输入与项目身份。
- 每条新真实用户输入至多生成一份已记录的自动检索结果，包含零命中。Input Batch 保留各输入边界并共享有限总注入预算；Explicit Steering 的新正文保留新输入身份。工具续步、同一输入重试和重启复用已保存结果，不因继续执行重复检索。
- 自动结果先受当前纠正和遗忘规则过滤再注入；重用结果也必须执行过滤。显式发起的新搜索可使用新查询，但不能借此把 helper 返回冒充用户输入或自动重复填充。
- 召回内容携带用户/助手/工具/helper 等来源与时间，原文可追溯。历史表达是资料，不自动升级为当前指令；当前用户表达优先。可选召回不可用时明确说明或降级继续，不伪造零命中，遗忘过滤仍必须有效。

### 7. 记忆写入、纠正与遗忘

- 复用压缩结束的边界，后台提炼该次压缩实际覆盖的原始对话，不能用有损摘要替代证据。记录已处理范围，重启或重复回调不重复写入。
- 明确要求记住、纠正或忘记时立即处理，不等后台提炼。主助手统一写入共享记忆，helper 只提交候选；后台提炼也经同一写入边界校验来源和当前版本，避免覆盖已经生效的纠正。
- 用户事实、偏好和关系判断必须关联真实用户原话；助手推断、工具输出和 helper 报告不能独立充当这类事实的证据。记录 add、supersede、retract 及原条目关系，当前表达替代冲突旧条目，不能简单并列相反断言。
- 默认忘记删除或撤回对应画像内容，并持久记录相关来源的自动召回排除规则；保留原始对话。后台提炼、主题浮现、快照重建和历史检索结果复用都遵守排除规则，不能在 reset 或重启后重新学回。
- 遗忘立即使受影响快照、摘要和追加材料失效；保留与当前任务有关但不包含被遗忘事实的必要进度。保留原始对话不等于允许通过旧派生摘要自动重新注入。
- “彻底删除”是处理原始记录的独立意图，不能仅执行默认忘记后宣称已物理清除。其物理范围与恢复/备份处理另行明确，本规格不承诺尚未确定的全面删除能力。

### 8. 压缩与恢复

- 先复用 Pi Durable 的容量触发和后台压缩，使用当前原生配置作为起点；不增加固定空闲时长触发，也不另开一次模型调用为每个工具制作摘要。
- 压缩保留近期对话原文，以及目标、约束、决策原因、已完成/进行中/受阻事项和下一步的简洁摘要。必要来源保留路径或稳定引用；旧工具细节退出活动上下文，通过归档检索与分页回读找回，不恢复成历史全文。
- 先验证原生 Done、In Progress、Blocked、Key Decisions、Next Steps 与 Critical Context 是否满足要求，再做必要适配；不新增强制逐工具字段清单或平行进度表。
- 摘要帮助模型判断已做什么、结果如何及是否还需继续；Durable 的已确认结果与外部效果核验才是执行事实。摘要不能将未知效果写成成功，也不能因缺少细节而重跑已经确认的操作。
- reset 仅重置主 Session 上下文并更新记忆快照，保留长期记忆、原始记录、归档、队列、执行进度及 helper 身份。压缩与记忆接入不改变现有 FIFO、steering、暂停和恢复语义。

## Testing Decisions

主验收边界已经用户确认：复用现有 Assistant Service 集成夹具，经真实 Pi Durable、可控模型 HTTP 端点、实际工具和持久存储驱动输入，检查模型实际收到的请求、用户输出、工具效果、归档分页与重新打开服务后的行为。尽量在这一条高层入口覆盖完整流程，不把仅验证内部格式化函数或 mock 调用次数作为最终证据。

1. **前缀与快照**：连续真实输入、工具续步和 reopen 后捕获 provider 请求，确认工具/system 顺序、同代快照实际内容、已保存结果视图稳定，新材料按边界追加。新增记忆能影响下一次请求；纠正立即覆盖旧材料；压缩/reset 后新快照按规则生成。对 provider 编码后的内容断言，不只比较内部 prompt 对象。
2. **长输出卸载**：工具产生多页日志、错误输出和单行超长内容，检查首次请求中只有受限视图、关键状态及真实可读引用；连接器进度与最终结果也不能绕过限制。回读检查行/字节上限、下一位置、末页、超长单行持续推进和重组后不丢不重。一次选择只读取所需页，不自动读完整件。
3. **归档再发现**：先产生修复前失败与修复后成功两份相似记录，经压缩使旧引用不再出现在摘要，随后重启。由模型通过固定入口按命令、时间或关键词搜索，获得有界候选并选择正确记录分页读取。验证搜索分页、空结果、已知引用直读以及原件不可用时的真实报告。
4. **类型与媒体**：混合文本、图片和资源结果保持可读取来源，主请求没有图片 base64 文本膨胀；简单用户图片仍可处理。批量素材在送入主模型前完成路由，helper 能从真实路径读取 manifest 对应材料，主助手只按需读取选定证据。
5. **记忆生命周期**：通过真实用户输入触发档案、主题与原文召回；观察实际来源、角色、预算、去重和当前输入查询。工具续步、同一输入恢复和 reopen 不重复召回，包含零命中；新输入和显式搜索仍能查询。合批输入和 steering 保留身份，不把内部材料当成用户事实。
6. **治理与遗忘**：原始用户表达形成有来源记忆，后续纠正产生替代关系；助手或 helper 的无用户证据断言不能写成用户事实。压缩后的提炼只处理其原始覆盖范围。忘记后立即检查快照、摘要、主题、已保存召回及后台提炼，跨 reset/reopen 不再自动引入被排除内容；原始记录仍在，系统不声称彻底物理删除。
7. **压缩后续接**：通过同一服务入口配置可控的小上下文窗口或支持的压缩设置，触发真实原生压缩。检查近期原文与必要摘要能继续任务、定位相关证据；不要求每个工具出现在摘要中。真实工具效果计数证明已完成操作不因压缩、reset 或重启重复执行，未知效果继续走既有核验与暂停流程。
8. **持久化失败边界**：在工具已执行后模拟归档写入失败，核对状态如实呈现且不重跑外部操作；模拟记忆检索不可用，核对不伪造命中或空结果，遗忘规则仍生效。复用既有 Durable 效果计数和强杀恢复手法，避免另造执行恢复测试框架。
9. **通用委派与回归**：至少使用一种非视觉的大资料子任务及一个媒体场景，验证同一 helper 复用、简洁成果交接和按需来源读取。复用既有 helper 身份恢复、实际文件成果、返回队列和 stop 未知状态用例；现有 FIFO、合批、steering、文件交付、暂停/resume 与非导入历史行为继续通过。
10. **真实质量与收益**：确定性协议测试通过后，以真实模型和 helper 补充验证用户偏好/项目经历检索、纠正后回答、遗忘后回答、摘要续接和资料分析质量。对同一任务记录主上下文规模、总输入/输出、缓存 usage、委派调用与耗时；分别报告主上下文保护和全链路成本，不以本地端点模拟出远端缓存命中，也不以配置为零的费用证明省钱。

现有先例包括 Assistant Service 的请求捕获与 reopen 夹具、Durable 已确认步骤复用和真实效果计数、子进程强杀恢复、helper 身份恢复与文件交付验收。旧记忆评测仅用于选择场景，不能证明当前生产入口已接入。本次交付是规格，不声称上述运行验收已经完成。

## Out of Scope

- 重写 Queue System、Durable Workflow、helper 调度或通用任务状态系统；变更现有权限、发布与外部效果核验规则。
- 迁移或自动导入旧 Host/Akasha 的历史数据，以及把所有工具全文写入语义记忆。
- 每轮删除历史工具消息、按问题动态删减工具定义、自动遍历所有归档页。
- 固定空闲计时压缩、另建逐工具模型摘要流水、强制每次摘要携带完整工具清单。
- 完整复制 Akashic 的图内核、算法、参数和文件写入机制；构建多用户记忆平台或全新图片传输协议。
- 尚未明确范围的原始数据/备份彻底物理删除、归档自动过期清理和历史存储迁移。
- 保证 provider 缓存命中、固定比例成本下降或 helper 必然比主助手省钱。
- 本次规格发布不包含运行时实现、部署或向上游推送代码。
