# 清退旧实现与遗留数据规格

Based on #225

权威规格：[Issue #226](https://github.com/CxHsin/nailong-bot/issues/226)，标记 ready-for-agent；本文件为同次发布的本地归档。

日期：2026-10-17。状态：待实现规格；清理范围来自已确认的设计选择。当前生产职责继续遵循 ADR-0011、ADR-0012、ADR-0013；本规格结束旧离线工具与旧 helper 导入兼容职责。

## Problem Statement

用户希望删除已经退休的代码，以及旧系统遗留在本地的记忆、event log 等资料。多代实现继续留在仓库，旧离线命令让已经退出生产路径的日志、投影和记忆依赖难以收敛；多代数据混在同一 data 根目录，又容易把当前正在使用的持久记录误当成旧日志。

当前 Personal Agent 的长期记忆、Akasha Recall、Durable Workflow 和队列仍是需要保留的功能。清理的目标是减少遗留负担，而非重置现役助手、取消功能或抹去当前工作。

## Solution

沿当前生产入口及实际调用关系，移除已被替代的实现和只服务于它们的测试、脚本与配置；同时退役旧日志离线诊断、旧迁移命令和旧 Pi helper 身份导入。仍被现役功能使用的共享模块继续保留。

对确认属于旧系统的本地数据执行一次性物理删除，不新增备份。完整保留实际现役数据空间及其队列、工作进度、helper、记忆、工具原件和发送回执。历史文档保留对应版本背景，当前说明只描述仍然可用的入口和能力。

## User Stories

1. 作为用户，我希望清理后仍能通过 Telegram 和 CLI 使用现役助手，以便清理不会中断正常交互能力。
2. 作为用户，我希望排队输入、Work Target 与 Routing Action 保留身份和进度，以便清理不会丢失或重复处理已提交的工作。
3. 作为用户，我希望 Durable Workflow 在重启后继续复用已确认结果，以便清理不会导致重复执行工具或外部操作。
4. 作为用户，我希望 Paused Work 仍等待明确继续，以便维护不会绕过暂停决定。
5. 作为用户，我希望现役 helper 的原身份和控制记录保留，以便后台工作仍可接回、补充和取消。
6. 作为用户，我希望现役 Long-term Memory、SELF 和主题资料保留，以便不必重新教授已经记住的偏好和背景。
7. 作为用户，我希望 Akasha Recall、主动搜索和原文读取继续可用，以便能够核查当前系统保存的来源。
8. 作为用户，我希望记忆纠正和 Default Forgetting 仍跨 reset、压缩和重启生效，以便清理不会让已撤回的旧判断重新影响回答。
9. 作为用户，我希望当前 Memory Snapshot 和压缩续接材料保留，以便现役上下文仍能正确继续。
10. 作为用户，我希望当前 Tool Archive 及其分页和检索引用继续可读，以便不会因删除旧工具原件而丢失当前证据。
11. 作为用户，我希望 Send Receipt 仍区分已发送和未知状态，以便维护不会导致重复发送。
12. 作为维护者，我希望删除旧记忆、旧日志和旧上下文实现，以便阅读代码时能集中于当前职责。
13. 作为维护者，我希望旧离线诊断与迁移命令连同专用依赖一起退役，以便不再维护已放弃的数据格式和执行入口。
14. 作为维护者，我希望仍有现役调用的共享工具保留，以便不因目录名称看似陈旧而破坏当前功能。
15. 作为维护者，我希望测试只继续保证现役职责，以便不必为已删除实现保留兼容壳或无意义测试。
16. 作为维护者，我希望旧测试中仍有价值的行为保证在当前集成边界保留，以便删旧代码不会同时失去现役回归保护。
17. 作为用户，我希望彻底结束旧 helper 自动导入，以便启动不再依赖旧会话目录。
18. 作为用户，我希望旧记忆、历史对话、event log、投影与旧工具原件按确认范围实际删除，以便本地不再残留无用资料。
19. 作为用户，我希望这次删除不额外复制备份或归档，以便不会把同一批旧资料换个位置继续保留。
20. 作为用户，我希望看到删除的确切路径和影响，以便知道哪些旧记录将永久失去。
21. 作为用户，我希望当前配置、凭据、现役数据和独立工作成果保留，以便清理只影响已退休资料。
22. 作为维护者，我希望 README、操作说明、命令和配置示例与实现一致，以便不会再按过期入口操作。
23. 作为维护者，我希望旧研究、ADR 与验收记录仍可追溯到当时版本，以便保留历史原因而不误称其为现役保证。
24. 作为维护者，我希望获得实际检查结果、测试条数和清理摘要，以便区分规格、代码提交、本地数据清理和生产运行状态。

## Implementation Decisions

1. **现役职责保持。** Assistant Service、Queue System、Durable Workflow、上下文输入路由、Delegation、分层记忆、Memory Snapshot、Tool Archive 和 Channel 的实际行为继续遵循当前契约。现役数据模型不因清理而重建、迁移或清空；旧数据物理删除是本次明确请求的独立维护行为，不是 Default Forgetting 的新默认。
2. **按使用者清退。** 从 Telegram、CLI 和受支持的生产装配链追踪源码、脚本、导出、测试与依赖。候选包括旧 Host/Task、旧记忆图内核与学习、旧模型执行、旧 Runtime Event Log、历史编解码、旧上下文投影、压缩、回放及离线诊断。目录、名称、年代或仅剩测试调用都不是单独的删除证据；先确认职责已结束，并保留当前路径仍使用的共享能力。
3. **旧离线契约结束。** 从包命令、构建输入、脚本、专用测试和当前说明中一起移除 run:diagnose、context:diagnose、migrate 的旧系统入口及专用实现。不再提供查询、迁移、恢复旧日志的兼容能力，也不以隐藏入口、兼容包装或新工具替代它们。只在确实失去所有保留使用者时移除依赖。
4. **旧 helper 导入结束。** 删除启动时读取旧会话索引及 helper 档案的导入路径、legacyDataDir 接口和 ASSISTANT_LEGACY_DATA_DIR 配置。当前空间里已有的 Helper Observation、原身份核对、控制进度和返回接收机制继续工作。不得因结束导入而删除当前 helper、盲目重派，或假定外部工作已经结束。
5. **测试随职责收敛。** 删除仅验证退休行为的测试与夹具；仍适用于当前系统的保证优先复用现有集成测试，确有缺口才迁移有价值断言。比如旧导入失败触发的资源释放测试，若该保证仍适用于其他当前启动失败，则在现有启动边界保留；无需为每个旧测试制造新的等价机制。
6. **本地数据一次性清理。** 核对实际配置与运行服务使用的数据空间，列出每个待删除目标的绝对路径、用途、现役引用关系和损失范围。删除范围仅包括已确认遗留的记忆、历史事件、投影和 checkpoint、工具原件、旧会话、迁移记录、原型及备份。解析并检查目标确实位于确认的项目数据范围内，目录重解析点也不能让删除越界。不要把所有日志或 SQLite 文件归为旧数据，也不要整体清空 data 根目录。
7. **保护现役资料。** 完整保留现役队列、执行进度、路由与工作状态、helper、来源及遗忘关系、记忆档案与快照、原始工具结果、媒体和发送回执。配置、凭据、外部 helper 工作目录、独立成果及其他未提交文件不在清理范围。对仍有使用者的目标先核对和处理真实占用；未知占用不会扩大删除范围。
8. **采用直接删除。** 用户已选择直接物理删除确认过的遗留数据，不另建备份、打包归档或新增 Git 跟踪。报告删除清单、成功与失败、实际空间变化；失败不能被报告为清理完成。此次维护不引入通用清理框架、自动过期、定时任务或启动自动删除。
9. **文档保持版本语义。** 同步当前使用说明、环境示例、包命令和已接受 ADR 的实现说明。历史 ADR、研究、旧验收保留当时结论及日期/基准；被删源码的历史链接使用核对过的提交永久链接，当前行为链接到现行说明。说明新的退休决定与旧保留承诺之间的关系，不把计划写成已部署事实。
10. **交付分开记录。** 按仓库要求在 development 同步最新 main 后实现、验证和提交。源码提交不能证明忽略目录里的数据已经清理；本地删除也不能证明生产服务已经运行新版。各自交付相应证据，推送、PR 和生产进程操作遵守用户授权及仓库流程。

## Testing Decisions

1. **主验收边界沿用 Assistant Service。** 复用现有 assistantFixture/createAssistant、临时数据目录、受控 Provider 与 helper 替身；通过真实 Input Event 触发服务，观察实际模型请求、用户输出、工具成果和持久记录，再关闭并重开验证恢复。优先用这一现成高层边界覆盖各模块协作，不为旧代码删除新增平行测试接口。
2. **队列和执行。** 复用现有队列、路由、Durable 及恢复测试，覆盖输入去重和 FIFO、补充与取消、暂停后明确 resume、reset 保留工作、已完成步骤复用和未知外部效果处理。关键断言是实际处理与持久进度，不只是状态名称或助手自述。
3. **现役 helper。** 复用已登记 helper 跨重启、reset、结果确认和控制投递的测试，证明接回仍使用原身份且不重复派发。删除只验证旧空间导入的断言；保留启动资源正确释放、现役空间隔离等仍有效保证。
4. **现役记忆、上下文和工具归档。** 复用共享记忆立即可见及跨 reset/reopen、来源校验、主题与 Akasha 原文、纠正与遗忘、快照和原生压缩续接、归档分页与发现测试。断言实际请求、可读原件和派生材料，不以 SQLite 文件仍存在代替内容可用的保证。
5. **Channel 与正式入口。** 继续运行已有 Telegram/CLI 行为测试，涵盖自然语言路由、真实文件成果交付及发送状态。此次删除不把真实模型费用或真实 Telegram 重测设为默认门槛；已有受控边界发现入口相关缺口时，针对该缺口补必要验证。
6. **实际清理核对。** 删除前核对现役数据边界并记录目标清单；删除后确认清单中遗留目标已经移除、现役目录与已知必要记录仍可用，并检查保留入口不再依赖旧目录。对需要稳定快照比较的检查先处理相关写入占用；在临时副本中做会写入的恢复验证，避免为验收修改生产数据。无需为一次性人工删除建立专用数据库或只断言源码字符串的测试。
7. **必跑检查。** 实施完成运行 npm run typecheck、npm test、npm run build、npm run docs:check，记录实际测试条数和结果；新增文档先暂存。补充定向调用与文档语义核对，确认退休命令、配置及历史链接没有留下错误说明。规格发布阶段的文档检查不能冒充实现验收。

## Out of Scope

- 取消或重写现役长期记忆、Akasha、工具归档、队列、路由或 Durable 能力。
- 清空或重置现役数据空间，删除现役记忆/执行/发送记录，改变 reset、Default Forgetting 或取消语义。
- 将旧历史、记忆、工具轨迹或 helper 自动迁移进新系统；保留旧离线查询与恢复能力。
- 删除历史研究、ADR、旧验收材料，重写历史证据或顺便清理无关未提交文件。
- 增加自动清理、备份系统、保留策略引擎、通用迁移框架或新的兼容层。
- 重构无关当前模块、增加新连接器、改进模型性能或改变产品交互。
- 由本规格发布触发源码删除、本地数据删除、上游推送、合并或生产服务重启。

## Further Notes

- 勘察基准为 c316227fb5519b186ddbb8a388f07ecf0bea0f54；发布时仍未实施清理。实际候选与依赖在实施时以稳定工作区重新核对。
- 默认现役目录为 data/pi-durable-v1。勘察时 data 共约 484.38 MiB / 3643 文件，现役约 1.54 MiB / 21 文件，其余约 482.85 MiB。data 不受 Git 跟踪，数字是当前快照，不能当作必须删除所有其余字节的规则。
- 已发现的大头包括 data/context-projections、data/backups、data/personal-history-backups、data/prototypes、data/runtime-v2.sqlite、data/events.sqlite 及 data/tool-results；旧 Pi 目录为 data/pi-assistant-v1。完整可执行删除清单须按上述规则核对，不能把这组候选直接当作递归删除命令。
- 默认旧 Pi 目录仅见 auth.json 与 owner.sqlite，没有旧会话/helper 索引；不能据此声称外部 helper 全部结束。本地 .env 与勘察进程环境未覆盖数据路径，但这不证明既有服务的启动环境。
- 设计结论见 #225。用户已授权直接删除确认过的旧数据且不新增备份；执行前仍须呈现确切路径和影响，超出已确认边界的资料不能因文件位于 data 下而删除。
- 测试采用既有高层集成边界；若用户在发布前提出真实链路的额外硬性要求，更新本规格的 Testing Decisions。
- 本 Issue 是实现的权威规格，标记 ready-for-agent；后续拆分的实施任务应使用 Part of 关联，并分别交付源码验证与本地数据清理证据。
