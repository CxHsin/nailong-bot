# 稳定系统内容、环境基础指令与 SELF 文件规格

Based on #233

正式规格：[Issue #234](https://github.com/CxHsin/nailong-bot/issues/234)，标签为 `ready-for-agent`。

日期：2026-10-17。设计依据为[结论 Issue #233](https://github.com/CxHsin/nailong-bot/issues/233)及 [ADR-0015](../adr/0015-system-context-order-and-self-file.md)。规格基准为 development 的 `2e712fc`。本轮只制定规格，不表示功能已实现、数据已迁移或服务已部署。用户已确认采用现有 Assistant Service 集成夹具作为主要测试入口，另补配置读取的入口测试。

## Problem Statement

用户希望助手的系统内容按变化频率排列，让基础指令在记忆变化、压缩和恢复状态改变时尽量保持可复用前缀。当前基础 instructions 位于项目、技能、记忆和条件性恢复提示之后，只保证固定顺序，没有充分保护更稳定的基础部分。

用户不希望再单独维护 `system-prompt.md`，也不希望身份、人设与相处方式散落于基础 prompt 和数据库生成的 SELF 中。当前直接编辑 SELF 档案不会生效，启动会重新导出覆盖；修改基础 prompt 后，已有 Conversation 又会沿用 Durable 保存的旧 instructions。用户需要可以直接维护的 SELF、清楚的更新边界，以及保留来源、纠正和遗忘的长期理解。

## Solution

基础指令直接由环境配置提供，支持在 `.env` 维护多行文本。SELF 文件成为身份、人设、相处方式、关系理解与表达习惯的唯一当前内容来源。程序通过 SDK 公开接口依次组装基础指令、skills 目录、项目指令、SELF 快照、MEMORY 快照；动态工作状态和新增材料在后续输入边界追加。

助手可以依据真实交流更新 SELF 中的关系理解和表达习惯；身份与基础人设仅按用户明确要求改变。同代 SELF 快照固定，普通更新即时追加，压缩或 reset 后归并，遗忘立即清理派生材料。重启后已有 Conversation 采用最新基础规则和人工编辑的 SELF，同时保留对话、队列、Durable 执行进度与 helper 身份。

## User Stories

1. 作为用户，我希望基础指令位于系统内容最前面，以便较频繁的记忆更新不会改写它之前的前缀。
2. 作为用户，我希望 skills、项目指令、SELF 和 MEMORY 各有明确顺序，以便理解实际发送给模型的内容布局。
3. 作为用户，我希望在环境配置中直接维护基础指令，以便不再管理独立的系统 prompt 文件。
4. 作为维护者，我希望基础指令支持中文、实际换行和引号，以便通过现有启动入口维护可读规则。
5. 作为用户，我希望人设、身份和相处方式统一归入 SELF，以便不必同时维护相互重复的描述。
6. 作为用户，我希望直接编辑 SELF 文件后能在重启时生效，以便控制助手对自己的定义。
7. 作为用户，我希望程序不再用数据库导出覆盖 SELF，以便我的人工修改不会丢失。
8. 作为用户，我希望只有明确交办才能改变助手身份与基础人设，以便普通聊天不会无意改变角色。
9. 作为用户，我希望助手能根据真实交流更新对我及关系的理解，以便长期相处可以积累有依据的认识。
10. 作为用户，我希望表达习惯能随交流调整，以便减少重复口头禅并采用我偏好的回答方式。
11. 作为用户，我希望理解和关系更新保留来源，以便能核查、纠正或忘记它们。
12. 作为用户，我希望 helper、工具和摘要不能伪装成我的原话写入 SELF，以便历史材料不会扩大授权。
13. 作为用户，我希望同一压缩代的 SELF 快照固定，以便连续工具续步保持稳定的输入前缀。
14. 作为用户，我希望 SELF 更新立即影响后续回答，以便不必等待压缩才看到纠正。
15. 作为用户，我希望更新通过追加材料生效，以便即时理解与稳定快照可以兼得。
16. 作为用户，我希望压缩和 reset 后使用最新 SELF，以便新上下文不必重复携带已经归并的增量。
17. 作为用户，我希望没有相关变更的重启复用实际快照，以便恢复不会无故重组系统内容。
18. 作为用户，我希望重启后已有 Conversation 采用最新基础指令，以便修改规则不再只对新会话有效。
19. 作为用户，我希望手动更新 SELF 后重启能更新已有会话，以便不必删除对话来切换身份内容。
20. 作为用户，我希望重启更新规则时保留历史和真实工作进度，以便不会重做已确认操作。
21. 作为用户，我希望当前恢复状态以动态材料追加，以便恢复提示出现或消失不会重排固定规则。
22. 作为用户，我希望忘记请求立即影响 SELF 和派生上下文，以便相关内容不再通过旧快照或摘要回来。
23. 作为用户，我希望纠正后的旧理解不能再次被后台学习恢复，以便当前表达持续优先。
24. 作为用户，我希望多个 Conversation 共享的 SELF 更新都能被正确接收，以便不同入口的理解保持一致。
25. 作为用户，我希望原有有效 SELF 理解在升级后得到保留，以便切换存储权威来源不丢失关系历史。
26. 作为用户，我希望迁移不会重新导入已退役、撤回或遗忘的内容，以便升级不推翻既有清理。
27. 作为用户，我希望新数据空间也有可用的初始 SELF，以便助手首次启动能具备既定奶龙人设。
28. 作为用户，我希望 SELF 写入失败时不会被告知成功，以便知道哪些修改实际落盘。
29. 作为维护者，我希望真实 provider 请求能够证明顺序和更新边界，以便测试不会只验证内部拼装对象。
30. 作为维护者，我希望保留其他记忆、路由、工具归档和恢复保证，以便这次职责调整不影响现役助手能力。

## Implementation Decisions

### 配置与内容归属

- 环境入口采用 `AGENT_SYSTEM_PROMPT` 提供非空基础指令文本，支持现有 Node 环境文件加载方式的多行中文内容。只校验非空，保留实际换行和正文，不把值当成文件路径或二次解释为转义模板。缺少有效值时启动给出明确配置错误。
- `AGENT_PROMPT_FILE` 退出生产读取路径，不保留旧 prompt 文件兜底或双重注入。直接嵌入 Assistant Service 的调用方仍可显式提供基础指令文本；无需为测试或内嵌入口另造配置框架。
- 基础指令包含遵循 SELF、项目和技能的使用原则、真实报告结果、授权边界以及固定的委派、归档和恢复核查规则。原默认 prompt 中的奶龙角色、核心性格、语气和相处方式迁入初始 SELF，基础指令不保留重复人设。
- SELF 沿用现役数据空间内已有 SELF 档案的位置和共享范围，不放到 Work Directory 中另建一份。内容按身份与基础人设、相处原则、关系理解、表达习惯组织；人工可以编辑，程序管理的条目保留稳定身份与来源定位。既有项目范围的内容保留范围，不因汇入共享文件而变成全局断言。
- MEMORY、主题、Akasha 原始来源、版本、遗忘排除和 Durable 执行记录继续使用现役存储职责。数据库可以维护 SELF 的来源、版本、变更及快照元数据，但不能作为当前 SELF 正文的第二个权威来源；普通记忆导出停止写 SELF。

### 系统组装与 SDK 衔接

- 通过公开 extension sections 保证编码后的有效顺序为基础指令、skills、项目指令、SELF、MEMORY。skills 保留目录式发现，项目材料沿用现役加载规则。基础指令不能既作为首 section 又通过旧 instructions 出现在末尾。
- 新建和恢复已有 Conversation 使用同一套配置路径。打开已存在 root 后显式清除旧 instructions，使用公开配置接口更新必要的 agent 状态；不修改 SDK 私有实现，不替换 provider 编码器。
- 当前未知外部效果的调用身份、状态和核查材料退出条件性 system section，在现有恢复输入边界追加。实际执行约束和 resolve 流程保留；仅移动材料位置，不能解除现有防重复执行的约束。
- system 后的压缩摘要、近期历史、Input Event 原文与身份、媒体、主题/原文召回、Work Supplement 和 helper 返回维持各自语义和边界。SELF 里的身份设定是配置，关系推断是有来源的理解；历史资料不能伪装成新的用户指令。
- 工具定义继续由 SDK/provider 按现役协议编码，不按问题裁剪。支持对话中系统更新的协议与需要折叠到开头的协议均须得到一致的有效 section 顺序；不要求不同 provider 的 JSON 结构相同。

### SELF 读写、来源与修改职责

- 在现有共享记忆职责内建立统一的 SELF 读写边界，供模型主动写入、纠正、遗忘及压缩后原文提炼复用。现有 SELF 类型的记忆调用改为维护权威文件，不能一条写数据库正文、另一条直接改文件再相互覆盖。
- 主助手根据用户当前原话判断是否明确要求改变身份或基础人设；仅明确交办允许这类变更。关系理解和表达习惯可以从真实交流更新，须保留可核对依据；身份设定与关系提炼分别处理，后台提炼不得自行重写角色。
- 保留原有原始用户来源、精确引用、当前版本、纠正目标、撤回及遗忘排除校验。helper 只提供候选；工具、helper、模型摘要和助手自述不能被登记为用户原话。导入的初始人设和人工文件编辑标为本地配置来源，不伪造为对话中的用户引语。
- 文件是当前正文的唯一来源。模型读取、显式查询、纠正和自动召回必须以文件中的当前有效内容为准，旧数据库 SELF 正文不能独立重新浮现；既有原始记录仍按原角色和来源提供证据。
- 写入遵循现有 Assistant Service 对同一数据空间的独占与并发模型，多 Conversation 和后台提炼共用版本校验，不能互相覆盖。持久写入成功后才能确认和投递变更；写入失败或版本冲突反馈真实结果，不能产生只在上下文中存在的成功更新。
- 文件写入与元数据更新中断后，重开须核对实际文件版本与已保存变更，采用已确认内容，不盲目重复写入，不用旧数据库正文恢复覆盖人工修改。实现采用满足这些保证的最小持久化方案，不引入通用多存储事务框架。

### 快照、即时生效与重启

- SELF 与 MEMORY 分 section 保存并注入。同一 Conversation、Session 和压缩代内持久保存实际快照正文、内容版本及来源；新增 SELF section 后仍保持现有常驻材料总预算，不能让两份快照各自无界增长。超预算内容保留可分页定位的引用，原件不截断。
- 助手成功更新 SELF 后，通过现有带身份的变更投递进入下一次可用的模型请求，包括同一 Processing Turn 的工具续步。其他已有 Conversation 在下一输入边界接收尚未消费的变化。投递可跨重启核对，不重复添加同一变化。
- 普通更新不重写同代 SELF 快照。当前纠正通过增量明确替代旧理解；压缩或 reset 后生成新 SELF 快照，增量通过版本衔接避免重复归并。压缩后的关系提炼继续只使用真实覆盖的原始用户记录。
- 服务重启是基础指令和人工编辑 SELF 的加载边界。文本确有变化时，已有 Conversation 的下一次请求采用新规则或新 SELF 基线；无需用户 reset，不丢失近期历史、压缩摘要、排队输入、暂停状态或 helper 身份。更新内容不能被旧派生材料重新覆盖。
- 无变化的重启复用已持久保存的实际快照，不因新版本记忆文件存在就伪造同代快照。如果此前助手更新已经以增量投递，重启仍复用同代快照及该增量，不能把普通恢复当成一次隐式压缩。
- 暂不监听人工文件修改，也不在每轮扫描文件以热加载配置。身份/规则更新和内容版本相互关联，不因单纯服务重启制造无意义的新版本。
- reset 继续只重置主上下文，不取消队列、工作或外部 helper，也不撤回长期记忆。Durable 与外部证据仍决定哪些操作已完成，SELF 不能替代执行状态。

### 纠正与遗忘

- 明确遗忘立即从当前 SELF 撤回对应内容，并通过已有关联来源使受影响的快照、旧增量、自动召回、工具记忆结果、助手派生回复和压缩摘要失效。范围包括其他 Conversation 和重启/reset 后的请求，不等待下一压缩代。
- 被修改的人工配置或身份内容同样须有可定位版本，不能因它不是自动学习条目而绕过后续纠正和遗忘。针对文件内容的明确修改只影响对应内容，不把无关身份、关系或工作进度全部清空。
- 受影响摘要继续从存活原文与实际 Durable 记录定位重建，保留无关目标、进度和已确认效果。后台提炼、旧增量重投递、迁移和旧数据库数据不能恢复已遗忘或被替代内容。
- 默认遗忘仍保留原始记录并排除自动召回和学习；物理删除不属于本规格。

### 现役迁移与文档

- 仅迁移现役助手数据空间，不读取 ADR-0014 已退役的 namespace 或重新引入旧 Host 数据。新数据空间以迁入 SELF 的现有默认奶龙人设初始化；默认角色不由模型临时生成。
- 升级先识别并保留已有 SELF 文件及人工改动。现役有效的旧 SELF 条目、条目身份、引用、版本、范围与排除关系需要一次性衔接；文件缺失而存在有效旧条目时据此初始化。旧文件与数据库有分歧时，不能由数据库覆盖文件或复活人工已删内容。
- 初始化、格式衔接与完成标记必须可重复重开验证，不能在每次启动重生成文件；中断后根据实际文件及迁移状态续接。原有有效 MEMORY、主题、原文来源、归档和 helper 资料保留。
- 默认基础指令与 SELF 初始内容按职责迁移；自定义旧 prompt 的内容由明确的升级说明指导迁入新配置或 SELF，不再由生产入口自动读取旧 prompt。缺失配置、不可读文件或迁移失败要返回可操作错误，不能静默切回旧来源。
- 同步环境示例、正式 CLI/Telegram 入口说明、操作文档及现役领域定义，明确谁是权威来源、更新时机和迁移方式。历史结论与验收保留基准并链接到后续决定；移除已退役 prompt 文件的现役引用与专用读取代码。

## Testing Decisions

用户已确认：主要复用 Assistant Service 集成夹具，通过临时数据目录、本地模型端点和真实 SDK/provider 编码观察外部行为；配置读取补少量官方入口测试。仅在实际持久化故障无法通过现有入口复现时增加针对性的存储故障注入，不为每个内部函数建立测试层。

好的测试应断言实际文件、模型收到的消息、持久恢复与真实操作次数，不只比对内部 section 数组、模拟内部私有方法或以助手自述证明完成。现有实际编码前缀与 reopen、共享记忆增量、原生压缩续接、遗忘摘要重建、CLI 子进程、helper 重启恢复测试提供先例。

验收至少覆盖以下外部场景：

1. **配置入口**：官方入口读取多行中文基础指令，保留换行和引号；缺失/空白新值报明确错误；仅存在旧文件配置不能悄悄回读；基础指令只出现一次。
2. **实际布局**：让基础、技能、项目、SELF、MEMORY 各有独特标记，在实际 provider 请求中断言有效顺序及各自唯一性；保持工具定义稳定。对项目已支持的三种模型协议覆盖编码契约，不新增生产适配器。
3. **动态恢复材料**：让未知外部效果出现并完成核查，证明固定 system 前缀未因具体状态变化而重排，核查材料在动态边界送达，原有约束与未知效果暂停行为仍有效。
4. **文件权威性**：创建已有 SELF，加入人工标记，再执行 MEMORY/主题导出、服务重启与模型输入；标记保留且进入模型，数据库旧正文不能覆盖或重复注入。
5. **修改范围与依据**：真实用户原文支持的关系/表达习惯更新成功；错误引用、helper 来源和已排除来源失败；身份变更有明确当前用户交办。后台提炼只更新允许的理解，不更换基础角色。
6. **同代即时更新**：通过公开记忆调用更新 SELF，断言文件落盘、下一次工具续步收到变化、原 SELF system 快照不变；再次调用不能重复投递。
7. **共享与重开**：两 Conversation 先建立快照，再更新 SELF；各自下一边界收到同一新事实一次，重开后不会漏投、重复或退回旧内容。
8. **无变化恢复**：连续交互、工具续步和无修改重启后，provider 的既有有效前缀与实际快照保持一致，而非只比较版本号。
9. **人工修改与基础配置更新**：在停止服务后同时修改基础指令和 SELF，重开同一个 Conversation；下一请求采用新文本、清除旧 instructions 重复项，保留近期历史、既有摘要与未完成目标。
10. **压缩与 reset**：普通增量在真实原生压缩和 reset 后归并到新快照；近期原文、来源定位及有待继续的工作保留，已完成副作用不重做，helper 身份不丢失。
11. **纠正与遗忘**：SELF 事实经纠正或遗忘后，检查当前文件、同代快照、已投递增量、跨会话自动召回、工具结果和压缩摘要；旧事实及派生改写不再进入模型，原文物理保留且无关工作仍能继续。
12. **学习排除**：遗忘后再次压缩、后台提炼、重启和初始化，均不能重新学回旧 SELF；人工加入的对应内容也能被明确撤回并得到来源版本记录。
13. **现役迁移**：覆盖旧生成 SELF、已人工修改 SELF、文件缺失但有有效数据库条目、新空数据空间四种情况；排除已撤回条目，重复重开不覆盖、不重复迁移，不导入退役 namespace。
14. **持久化失败**：覆盖文件写入失败、版本冲突及文件/元数据更新交接处中断；不能报告成功或投递未落盘更新，重开不丢失人工内容或重复应用已确认变化。复用现有恢复风格，必要时采用针对性故障注入。
15. **预算**：SELF 与 MEMORY 合计常驻预算以及本批增量预算继续有界，超限材料可按引用读取，实际完整文件和来源不丢失。

受控集成测试验证布局、生命周期和来源校验；“当前用户是否明确改变身份”与自然关系理解还需真实模型验收，不能用固定响应的假模型证明语义质量。真实验收至少覆盖人设保持、明确改人设、表达习惯更新、纠正与遗忘，并记录所用模型、实际输出和可得 usage。缓存收益只报告 provider 实际提供的指标。

实现完成时运行受影响测试、完整测试、类型检查、构建和文档链接检查，记录实际测试条数及证据基准；相关写入停止后再做综合验证。当前制定规格阶段只运行文档检查，不声称上述实现验收已通过。

## Out of Scope

- 本轮制定规格时修改真实环境配置、SELF 数据、应用代码、生产进程，或推送/合并分支。
- 新增文件监听、逐轮热加载、后台定时加载或固定空闲压缩机制。
- 将 MEMORY、topics、Akasha 或 Durable 执行记录整体改为文件权威来源。
- 为身份语义判断另建分类器、权限框架、通用事务平台或并行执行账本。
- 变更输入路由、FIFO、合批、取消、helper 委派协议、连接器或工具功能。
- 改造辅助路由/摘要模型的独立 prompt；本规格聚焦主 Personal Agent 的系统内容及相关 SELF 提炼职责。
- 重新导入退役资料、物理删除原始记录、改变默认遗忘含义，或承诺跨系统 exactly-once。
- 根据理论前缀直接承诺缓存命中率、费用或延迟收益。

## Further Notes

本规格细化 #233，并局部替代 #208 中基础 prompt 来源、SELF 导出权威性与系统排列的旧约定。ADR-0012 的来源治理、固定快照、动态追加、纠正与遗忘方向继续适用；ADR-0015 是本次职责调整的决策依据。

SELF 文件正文与旧快照是两个不同事实：前者回答“现在怎样定义自己”，后者回答“这一代实际向模型发送过什么”。数据库保存来源或快照并不意味着它仍可重生成当前 SELF。

既有 Conversation 的初始化参数不会自动更新已保存 instructions，不能只把新 prompt 填入新建 root 的参数就声称重启更新已实现。应通过公开 section/configure 能力处理已有会话，并以实际编码请求验证清除旧内容和保持历史两项保证。
