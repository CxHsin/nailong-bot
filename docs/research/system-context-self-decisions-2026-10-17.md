# 系统内容排序与 SELF 文件讨论

日期：2026-10-17。状态：设计方向已逐项确认，正式规格已整理；未修改运行代码或部署服务。核查基准为 development 的 `780f2ea`，Pi Durable 版本为 1.2.0。

已发布[结论 Issue #233](https://github.com/CxHsin/nailong-bot/issues/233)。架构决策见 [ADR-0015](../adr/0015-system-context-order-and-self-file.md)。

后续正式规格为 [Issue #234](https://github.com/CxHsin/nailong-bot/issues/234)，另有[本地规格归档](system-context-self-spec-2026-10-17.md)。其中细化配置入口、SELF 权威性与迁移、快照生效、纠正遗忘及经用户确认的测试入口；规格不表示已实现。

## 问题与当前实现

当前系统 section 为 project、skills、memory、material-routing、需要时出现的 external-effect-verification，最后是 SDK 追加的 instructions。基础指令位于记忆快照和条件性状态之后，不利于在这些材料更新后继续复用较稳定的前缀。仅保证同代顺序确定，并不等于按变化频率组织内容。

[环境入口](../../src/assistant/environment.ts)读取 `AGENT_PROMPT_FILE`，默认 `system-prompt.md`；[执行器](../../src/assistant/durable-executor.ts)将其传入 root agent 的 instructions。SDK 对已存在 root 直接返回，不重新应用初始化配置；当前 reset 也不更新 instructions。因此修改文件后，已有会话重启或 reset 仍沿用旧值。

当前 [SELF.md 由记忆数据库生成](../../src/assistant/memory.ts)，直接编辑不会导入，基础人设仍在 `system-prompt.md`。本轮决定调整这一职责划分。现役行为与历史验收仍以 [ADR-0012](../adr/0012-layered-memory-and-stable-context.md)及其验收记录为准，不能由本设计推导实现已改变。

## 已确认的内容归属与顺序

不再单独用 `system-prompt.md` 维护基础指令。内容按职责组织，由程序通过 SDK 公开接口统一组装：

1. `.env` 基础指令：简短启动与全局行为规则，包括遵循 SELF、使用项目指令和技能、真实报告结果、授权边界，以及固定的委派、资料处理与恢复核查原则。
2. skills 目录：技能名称、描述和路径，全文仍按需读取。
3. 项目指令：工作目录对应的项目要求。
4. SELF 快照：身份、人设、相处方式、对用户和关系的理解及表达习惯。
5. MEMORY 快照：用户事实、偏好等长期记忆。

system 之后保留压缩摘要、近期历史及本轮输入。当前恢复调用身份和状态、检索结果、helper 进展及记忆增量在对应边界追加。固定的恢复核查规则属于基础指令，具体待核查调用属于动态材料，不再作为条件性 system section 改写前缀。

SELF 会随交流演进，放在基础指令、技能和项目材料之后。快照仍明确标记历史理解不是当前用户指令，当前用户纠正优先；前后位置不改变资料的来源与授权语义。工具定义继续由 SDK/provider 编码，不按每轮问题动态裁剪。真实缓存收益须以 provider 请求及可得 usage 验证，顺序稳定不能证明远端命中。

## SELF 文件的权威性与修改范围

SELF 文件成为可以直接维护的权威来源；程序读取它，不能再由数据库导出覆盖。人设、身份和基本相处原则归入 SELF。其他记忆的数据来源不因本决定整体切换为文件；SELF 的来源、版本、纠正和遗忘能力仍须保留。

- 身份与基础人设由用户明确决定，例如是否仍是奶龙、核心性格是什么。普通聊天不能由助手自行改掉身份。
- 助手可以根据真实交流更新对用户及关系的理解，保留依据，当前纠正优先。
- 表达习惯可以随交流调整，例如减少口头禅、回答更简洁。

这里的文件权威性与上下文快照分开：当前 SELF 文件可以变化，已发送的同代快照仍有自己的实际内容和版本，不能用最新文件冒充旧快照。

## 更新生效与稳定前缀

- 服务重启后，已有会话也采用最新基础规则和人工编辑的 SELF；保留对话历史、工作进度及 helper 身份。暂不增加文件监听或逐轮热加载。
- 同一压缩代内，system 中的 SELF 快照固定。助手修改 SELF 文件后，将有来源的变化追加到当前上下文，立即影响后续回答，不等待下一次压缩。
- 压缩或 reset 时，将最新 SELF 合并为新快照。reset 继续只重置上下文，不取消工作，也不遗忘长期记忆。
- 未发生配置或材料变化的重启继续复用实际快照；重启加载人工修改属于明确的更新边界，不得为了缓存继续沿用旧规则。
- 明确遗忘时，立即清理 SELF 及其受影响的快照、追加材料、召回和摘要，不等待换代。既有来源治理与 Durable 执行状态的职责保留。

## 取舍与实现边界

相对于统一维护一份 MD，本轮选择 `.env` 基础指令与 SELF 身份文件，便于分别维护全局执行原则与持续演进的身份理解。相对于数据库导出 SELF，选择文件权威性使人工编辑可以直接生效，代价是后续实现需要衔接旧 SELF 数据、来源治理和快照，不能保留双向覆盖的两个权威来源。

SDK 的公开 extension sections 支持按声明顺序渲染；基础指令可以作为首 section，不必绕过编码器。迁移时须处理已有会话保存的旧 instructions，避免尾部重复注入；公开 configure 接口允许清除它。这是已核查的实现能力，不表示本轮已经执行迁移。

本轮只发布设计结论。环境变量名称、SELF 文件位置与结构、来源记录方式、已有数据迁移和正式验收用例由后续规格细化；未授权修改实际 `.env`、SELF 数据、运行代码、生产进程或上游分支。
