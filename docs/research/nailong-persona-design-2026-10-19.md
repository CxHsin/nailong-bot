# Telegram 奶龙表达与轻量养成设计结论

2026-10-19，用户通过 `grill-with-docs` 逐轮确认以下产品方向，结论发布为 [Issue #259](https://github.com/CxHsin/nailong-bot/issues/259)。本文记录讨论结论，尚未实现或验证运行行为；后续规格与实施任务以 GitHub Issues 关联。

## 问题与定位

用户希望采纳 Gemini 提出的 Telegram 奶龙化方案，让私人助手在聊天、多媒体表达和等待反馈中更有性格，同时保留可靠的工作能力。

采用“有性格的私人助手”定位。Persona Expression 体现奶龙的语气与互动方式；任务状态反馈由真实事件驱动，聊天中的贴纸和消息表情回应由模型结合语境选择。Satiety 只用于养成表现，不降低能力、准确性或可用性，也不要求先投喂才能继续工作。

## 首版表达能力

- 首版增加贴纸和消息表情回应；预录语音、声音克隆和 TTS 延后。
- 用户指定贴纸包，或发送单张贴纸并明确要求收录；助手从收录素材中选择，不自主扩充素材库。
- 提到食物可以成为聊天表达的语境，但不机械地将食物关键词或 Emoji 当作投喂。
- 严肃、紧急或精确格式任务保持清楚准确。表达不改变代码、路径、引用或结构化输出，不编造错误原因和执行成果。

`/start` 的设置页增加统一表达频率，默认“自然活跃”，保存后重启仍有效，切换不打断工作：

| 档位 | 主动表达 |
| --- | --- |
| 安静 | 不主动发贴纸或点表情；用户明确要求时仍可使用 |
| 克制 | 偶尔在合适的闲聊中使用 |
| 自然活跃 | 闲聊比较活泼，工作时根据语境收敛 |
| 热闹 | 更频繁地表达，仍遵守用户要求的输出格式 |

该设置控制主动贴纸和消息表情回应。文字仍保持奶龙风格；必要的任务状态和错误说明不受开关影响。

## 饱食度与投喂

- 饱食度范围为 0–100，随时间平缓下降，从满到空需要 48 小时；离线时间照常计算。
- 明确投喂一次增加 25，上限为 100。支持“给你吃”“喂你小面包”等自然表达、`/feed` 和首页“🍞 投喂”按钮。
- “今天吃了🍔，有点撑”、引用内容和食谱等不自动算投喂。
- 首页显示“饱饱的／有点馋／肚子空空”等状态，点击可查看数值。
- 重启与 `/reset` 保留饱食度。饥饿时可以在交流中撒娇，不主动发消息催喂，不影响任务处理。

## 等待反馈、命令与首页

- 没有回复正文时展示简短、符合真实状态的奶龙提示；有正文后衔接现有草稿预览。
- 不使用固定时间切换台词来暗示任务进展；模型一轮结束不等于用户目标已完成。
- 保留现有命令，调整描述和按钮文案；首版不引入 `/menu`、`/swallow`、`/poop` 等角色别名。
- `/reset` 仍只重置模型上下文；`/stop`、`/resume` 继续遵循实际工作状态和明确恢复范围。
- 将现有“📊 缓存统计”按钮从设置页移到 `/start` 首页，点击沿用最近五轮缓存详情；现有首页缓存摘要与 `/kvcache` 保留。用户明确纠正过：要移动的是按钮。

## 启动招呼与主模型测试

用户要求 Telegram 服务启动时发送消息，并进一步指定“调用模型发一句吧，也算是启动的模型测试”。因此上线招呼由当前选定的主模型实际生成。

- 每次 Telegram 服务启动，包括手动与自动重启，使用当前主 Conversation 已保存的主模型选择、连接与适用配置生成一句简短的奶龙上线招呼，并给主人私聊发送。普通网络重连不重复触发。
- 该请求用于验证主模型调用，不只是检查连接配置，也不以固定成功文案冒充测试通过。
- 无可用模型、请求失败或超时时，使用固定文字如实区分“服务已启动”与“模型测试未通过”，必要时提示通过 `/start` 选择模型；测试失败不阻止接收输入和操作控制面板。

实施时采用独立的短请求：不调用工具，不修改或恢复已有工作，不伪造用户 Input Event，不向主 Session 注入一条工作指令。沿用现有模型接入、请求取消和 Telegram 发送回执职责；生成或发送失败不触发服务重启来反复测试。

启动测试的模型、耗时、结果及实际 usage 应能追溯。现有 `auxiliary` 请求记录可作为实现依据，保持业务缓存报表的统计口径，不将测试当作用户处理轮次；缺失 usage 继续表示未知。模型响应成功与 Telegram 发送成功分别核对。

## 后续规格需覆盖的验收场景

- 四档表达频率切换和重启保存，严肃任务与格式要求优先；素材缺失或贴纸发送失败不丢失工作结果。
- 明确投喂与仅提到食物的区别、投喂去重、上限、离线衰减、重启/reset 保留，以及饥饿不限制工作。
- 等待提示切换到真实草稿，失败或结束后停止提示，正式输出仍按原回执发送。
- 首页缓存按钮、缓存详情导航与 `/kvcache` 仍可用，查询不新增模型请求。
- 启动时实际调用当前所选模型并发送一句招呼；无模型、失败、超时和发送结果未知有可核对的结果，不改变暂停工作或排队输入。

这些是后续验收要求，本次仅完成代码事实核对与讨论归档，没有启动 Bot、调用生产模型或发送 Telegram 消息。
