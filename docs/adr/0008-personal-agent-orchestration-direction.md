# Personal Agent 统一组织工作

2026-10-12 方向讨论。本文记录用户逐项确认的目标与仍待决定的边界；尚未形成完整规格或最终架构批准，不表示运行时已经迁移。当前实现仍见 [ADR-0007](0007-personal-host-native-sessions.md)。讨论源：[Grok Bot 架构文章](https://www.joyehuang.me/blog/20261011---alwaysonagents/post)、[Akasha 专项调研](../research/akasha-personal-memory-2026-10-12.md)。

## 已确认的方向

Nailong 的目标是持续共事的 personal agent，编码是其中一种能力。本体直接处理轻量工作和授权范围内的短操作；耗时、输出量大或需要独立上下文的工作委派给帮手。研究、整理与编码使用统一委派入口，保留不同帮手的能力和执行边界。herdr 是外部编码 Agent 的接入与管理桥梁，子任务结果回到本体，由本体继续处理完整用户目标。

本体工具保持少量通用能力。连接器工具按需发现和加载，不将全部工具说明常驻模型上下文；加载工具不等于授予执行权限。用户基本同意按明确范围授权、按成果与影响选择验收，而非所有工作使用同一套独立验收流水线。具体工具清单及可强制执行的授权机制尚未确定。

用户插话时主对话优先响应，独立后台工作继续；关联任务的补充要求交给对应工作，归属不明确时询问，明确叫停才取消。支持用户明确授权的长期职责和选择性汇报；尚无首个持续跟踪场景，不据此启动实际监控。

记忆采用有预算的自动背景召回并保留主动搜索，保留原话、时间、角色与出处，不生成稳定偏好档案。历史作为相关背景，当前问题、指令与事实判断优先；高召回分数不证明真实性、当前有效性或行动权限。上游图算法升级尚未决定。

## 与当前实现的差异

ADR-0007 把本地 Pi 与 herdr 定义为平级 Task executor；目标方向要求编码结果回到本体继续工作，需重审执行入口与结果归属。当前主会话的文件读取只限技能目录，通用文件操作与 Shell 在任务会话；当前任务会话直接暴露所有已连接 MCP 工具。当前记忆通过工具调用召回，尚未实现本次确认的自动背景注入。

保留任务身份、实际执行身份、重启对账、资源冲突、停止、授权和交付的可靠性职责；业务地位缩小不能视为外部进程生命周期管理已经解决。如何让委派与本体共享这些保证，需要后续规格和验证证据。

## 运行与交互边界（已确认）

第一阶段保留 Windows 本地部署，明确区分会话与工作状态、工具执行及外部 Agent 管理。本机休眠或关机期间不承诺持续执行；恢复后对账和续接。是否引入常开远端主机留待实际需求。

本体可以静默处理后台事件，按需要显式发送用户消息。直接交办及时确认，完成、受阻或需要决定时汇报；普通后台进度不逐条推送。运行时承担可靠发送及频率限制，具体交付恢复规则仍需规格化。

用户明确设定的工作约定独立保存，支持查看、修改与撤销，不包含推断的性格或偏好，也不自动扩大行动授权。此项是约定管理的目标，不表示新增稳定偏好档案；生效范围和冲突处理待规格确定。

## 工具、恢复与预算（已确认）

首版常驻能力候选为文件读取/写入/编辑、Shell、记忆搜索/原文读取、委派与工作管理、能力发现、显式发送消息。搜索、网页读取、计划及工作约定管理通过能力发现按需加载。这里定义能力面，不强行将一组能力合成一个接口，也不设固定工具数量指标；最终接口形状在规格中确定。

重启先核对实际状态，再续接能够确认的未完成工作。不确定的外部动作不盲目重做，已取消工作不复活；消息发送状态未知时保留待确认状态。执行器会话结束不能代替外部进程终止或副作用已完成的证据。

自主工作设置可调整的全局与单项上限，覆盖调用成本、帮手并发、自动重试及验收失败后的返工。达到上限后暂停并解释原因，本体不得自行无限增加预算。具体数值通过首阶段验证校准。

## 子任务记忆与首阶段（已确认）

子任务默认只接收目标、相关背景及必要工作约定，不自动获得全部个人历史。需要额外背景时向本体请求，由本体选择相关原文并保留出处；具体交互接口及隔离机制待规格确定。

第一阶段围绕四项验收：本体直接查询资料或整理文件并按需加载能力；委派研究或编码后接回结果继续完成整体目标，支持插话、补充要求和停止；自动召回相关经历且当前表达与事实判断优先；中途重启先对账再续接、未知副作用不重复执行、达到预算上限暂停。已有明确计划能力保留，长期职责等实际场景出现再扩建；浏览器与桌面操控、云端常驻、Akasha v2 升级留待后续，不作为首阶段依赖。

## 授权、验收与工作约定（已确认）

行动按用户目标和明确范围授权。例如整理指定目录中的 PDF，可在范围内读取、创建分类目录和移动文件；删除原件、上传文件及操作范围外的位置另行授权。子任务仅继承所需权限。Shell 的范围限制必须由执行机制强制落实，不能以提示词代替隔离；具体执行技术仍待决定。

运行时规定各类工作必要的检查，本体判断整体目标是否完成。研究核对来源与结论并标明不确定性，文件整理核对实际变化与数量，编码检查实际改动及测试证据，影响较大时增加独立评审。子任务完成只触发结果回传，本体可继续处理、要求返工或报告受阻；不再要求所有工作经过同一套独立验收。

工作约定默认限定当前项目或工作，全局生效需要明确表达。当前明确要求优先；冲突无法判断时询问。普通聊天与历史记忆不自动升级为约定；保存时向用户展示内容与范围，支持查看、修改和撤销。这是明确交办的规则，不是推断的固定人格。

这些目标调整 ADR-0007 的逐次动作审批及统一独立验收方向，尚未改变当前实现。

## 首轮实现路径与能力发现（已确认）

首轮保留现有 Host 与 Pi 原生会话执行内核，补齐本体委派、接回结果及继续完成目标的闭环；不把 Pi Durable 迁移作为本轮依赖。重启恢复能够确认的工作，未知副作用暂停对账。若现有内核遇到明确的恢复瓶颈，再通过小型验证决定是否迁移，不将实验性内核的持久化能力视为已经接入。

子任务成果保留其对应的要求版本。本体按最新要求重新检查，可复用部分继续使用，缺失部分补做；旧版本完成不能自动完成整体工作。已经发生的文件修改等效果如实保留并说明，补充要求本身不撤销既有动作。

能力通过 tool search 按当前工作发现：工具定义通过 API 原生结构进入对话上下文，不追加到模型的常驻工具前缀。有效的结构化发现记录保留时直接复用；记录被压缩移除或定义失效后重新发现，不假定 API 自动恢复已移除的记录。运行时保存可查询的发现记录并校验调用身份、工作范围与授权；上下文中的工具说明不等于执行权限。子任务只获得自身所需且获授权的能力。

区分请求传输目录与模型上下文：[OpenAI Responses tool search](https://developers.openai.com/api/docs/guides/tools-tool-search) 的客户端搜索可通过 tool_search_output 返回原请求中未声明的工具；[Anthropic tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) 仍要求每次请求提供完整的 deferred 工具定义，API 按对话中的 tool_reference 展开定义。二者都按需加载并保持常驻前缀稳定，不能简单以普通文本 schema 替代原生调用结构。Pi/provider 对这些结构的支持尚待核对，未支持时的兼容方案不能冒充原生机制。

## 后台结果与停止范围（已确认）

后台结果先持久化，排队等待当前回复结束后交给本体续接。结果带明确工作身份，作为执行材料进入上下文；本体在完成、受阻或需要用户决定时发送消息。当前回复与后台事件处理的串行衔接、重启后未消费结果的续接需要实现验证。

停止整项工作时取消其全部子委派，指定停止某个帮手时仅取消该帮手。已有成果保留，不自动回滚已发生的操作。外部进程未确认终止时显示正在停止并继续占用相关资源；其他独立工作继续。取消意图与迟到结果需核对，不能因结果返回而自动复活已停止的工作。

## 待决定

- 工作约定管理接口，以及消息发送的恢复规则。
- 工具接口与按需加载流程、记忆预算与去重、子任务背景请求与隔离机制、各类工作的检查配置。
- 持久化执行技术、委派恢复与取消机制、授权的可执行边界、预算配置与首阶段验收的具体证据。

在这些边界明确并获得用户对整体理解的确认后，再发布讨论结论 Issue 和实现规格。
