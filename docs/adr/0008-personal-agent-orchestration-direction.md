# Personal Agent 统一组织工作

2026-10-12 方向讨论，2026-10-13 用户调用 to-spec 将已确认设计转为规格。[设计结论 #166](https://github.com/CxHsin/nailong-bot/issues/166)、[规格 #167](https://github.com/CxHsin/nailong-bot/issues/167) 是讨论及实现规格的权威记录。本方向已按 #168–#173 在 development 实现；实际保证和未验证项见下方实现记录及[本轮验收](../personal-agent-acceptance-20261013.md)。[ADR-0007](0007-personal-host-native-sessions.md) 保留 #157 历史基线。讨论源：[Grok Bot 架构文章](https://www.joyehuang.me/blog/20261011---alwaysonagents/post)、[Akasha 专项调研](../research/akasha-personal-memory-2026-10-12.md)。

## 已确认的方向

Nailong 的目标是持续共事的 personal agent，编码是其中一种能力。本体直接处理轻量工作和授权范围内的短操作；耗时、输出量大或需要独立上下文的工作委派给帮手。研究、整理与编码使用统一委派入口，保留不同帮手的能力和执行边界。herdr 是外部编码 Agent 的接入与管理桥梁，子任务结果回到本体，由本体继续处理完整用户目标。

本体工具保持少量通用能力。连接器工具按需发现和加载，不将全部工具说明常驻模型上下文；加载工具不等于授予执行权限。用户基本同意按明确范围授权、按成果与影响选择验收，而非所有工作使用同一套独立验收流水线。具体工具、权限接口及受阻策略由 #167 规格和下方实现记录确定。

用户插话时主对话优先响应，独立后台工作继续；关联任务的补充要求交给对应工作，归属不明确时询问，明确叫停才取消。支持用户明确授权的长期职责和选择性汇报；尚无首个持续跟踪场景，不据此启动实际监控。

记忆采用有预算的自动背景召回并保留主动搜索，保留原话、时间、角色与出处，不生成稳定偏好档案。历史作为相关背景，当前问题、指令与事实判断优先；高召回分数不证明真实性、当前有效性或行动权限。上游图算法升级尚未决定。

## 讨论时实现差异（2026-10-12 历史基线）

ADR-0007 把本地 Pi 与 herdr 定义为平级 Task executor；目标方向要求编码结果回到本体继续工作，需重审执行入口与结果归属。讨论时主会话的文件读取只限技能目录，通用文件操作与 Shell 在任务会话；当时任务会话直接暴露所有已连接 MCP 工具。当时记忆通过工具调用召回，尚未实现本次确认的自动背景注入。

保留任务身份、实际执行身份、重启对账、资源冲突、停止、授权和交付的可靠性职责；业务地位缩小不能视为外部进程生命周期管理已经解决。共享保证的实现和证据见本轮验收。

## 运行与交互边界（已确认）

第一阶段保留 Windows 本地部署，明确区分会话与工作状态、工具执行及外部 Agent 管理。本机休眠或关机期间不承诺持续执行；恢复后对账和续接。是否引入常开远端主机留待实际需求。

本体可以静默处理后台事件，按需要显式发送用户消息。直接交办及时确认，完成、受阻或需要决定时汇报；普通后台进度不逐条推送。运行时承担可靠发送及频率限制，具体交付恢复规则已在 #167 规格及 Host/Channel 实现。

用户明确设定的工作约定独立保存，支持查看、修改与撤销，不包含推断的性格或偏好，也不自动扩大行动授权。工作约定已实现默认工作/项目作用域、明确全局确认及修订撤销；它不是稳定偏好档案。

## 工具、恢复与预算（已确认）

首版常驻能力候选为文件读取/写入/编辑、Shell、记忆搜索/原文读取、委派与工作管理、能力发现、显式发送消息。搜索、网页读取、计划及工作约定管理通过能力发现按需加载。这里定义能力面，不强行将一组能力合成一个接口，也不设固定工具数量指标；最终接口形状在规格中确定。

重启先核对实际状态，再续接能够确认的未完成工作。不确定的外部动作不盲目重做，已取消工作不复活；消息发送状态未知时保留待确认状态。执行器会话结束不能代替外部进程终止或副作用已完成的证据。

自主工作设置可调整的全局与单项上限，覆盖调用成本、帮手并发、自动重试及验收失败后的返工。达到上限后暂停并解释原因，本体不得自行无限增加预算。具体数值通过首阶段验证校准。

## 子任务记忆与首阶段（已确认）

子任务默认只接收目标、相关背景及必要工作约定，不自动获得全部个人历史。需要额外背景时向本体请求，由本体选择相关原文并保留出处；已通过 request_context/provide_context 保存定向请求和本体选定原文，不向孩子暴露全部历史工具。

第一阶段围绕四项验收：本体直接查询资料或整理文件并按需加载能力；委派研究或编码后接回结果继续完成整体目标，支持插话、补充要求和停止；自动召回相关经历且当前表达与事实判断优先；中途重启先对账再续接、未知副作用不重复执行、达到预算上限暂停。已有明确计划能力保留，长期职责等实际场景出现再扩建；浏览器与桌面操控、云端常驻、Akasha v2 升级留待后续，不作为首阶段依赖。

## 授权、验收与工作约定（已确认）

行动按用户目标和明确范围授权。例如整理指定目录中的 PDF，可在范围内读取、创建分类目录和移动文件；删除原件、上传文件及操作范围外的位置另行授权。子任务仅继承所需权限。Shell 的范围限制必须由执行机制强制落实，不能以提示词代替隔离；实际权限后端按证据匹配；本机完整受限隔离不可用时停止派发。

运行时规定各类工作必要的检查，本体判断整体目标是否完成。研究核对来源与结论并标明不确定性，文件整理核对实际变化与数量，编码检查实际改动及测试证据，影响较大时增加独立评审。子任务完成只触发结果回传，本体可继续处理、要求返工或报告受阻；不再要求所有工作经过同一套独立验收。

工作约定默认限定当前项目或工作，全局生效需要明确表达。当前明确要求优先；冲突无法判断时询问。普通聊天与历史记忆不自动升级为约定；保存时向用户展示内容与范围，支持查看、修改和撤销。这是明确交办的规则，不是推断的固定人格。

这些目标及实现取代 ADR-0007 的逐次 Shell 审批及所有工作统一独立验收方向；原 Host 可靠性职责继续保留。

## 首轮实现路径与能力发现（已确认）

首轮保留现有 Host 与 Pi 原生会话执行内核，补齐本体委派、接回结果及继续完成目标的闭环；不把 Pi Durable 迁移作为本轮依赖。重启恢复能够确认的工作，未知副作用暂停对账。若现有内核遇到明确的恢复瓶颈，再通过小型验证决定是否迁移，不将实验性内核的持久化能力视为已经接入。

子任务成果保留其对应的要求版本。本体按最新要求重新检查，可复用部分继续使用，缺失部分补做；旧版本完成不能自动完成整体工作。已经发生的文件修改等效果如实保留并说明，补充要求本身不撤销既有动作。

能力通过 tool search 按当前工作发现：工具定义通过 API 原生结构进入对话上下文，不追加到模型的常驻工具前缀。有效的结构化发现记录保留时直接复用；记录被压缩移除或定义失效后重新发现，不假定 API 自动恢复已移除的记录。运行时保存可查询的发现记录并校验调用身份、工作范围与授权；上下文中的工具说明不等于执行权限。子任务只获得自身所需且获授权的能力。

区分请求传输目录与模型上下文：[OpenAI Responses tool search](https://developers.openai.com/api/docs/guides/tools-tool-search) 的客户端搜索可通过 tool_search_output 返回原请求中未声明的工具；[Anthropic tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) 仍要求每次请求提供完整的 deferred 工具定义，API 按对话中的 tool_reference 展开定义。二者都按需加载并保持常驻前缀稳定，不能简单以普通文本 schema 替代原生调用结构。当前已使用 per-Session provider 适配保存这些原生结构；不支持原生搜索的端点不会曝光专用工具目录。

## 后台结果与停止范围（已确认）

原生工具搜索为首轮必需能力，包含 provider 请求、响应、历史记录与压缩后的验证；Pi 0.73.1 的原始 provider 未支持这些结构，现已在公开 streamFn 边界适配。按配置模型提供支持，不支持的接口明确报告能力缺失，不以不断追加普通工具定义替代已确认的机制。

后台结果先持久化，排队等待当前回复结束后交给本体续接。结果带明确工作身份，作为执行材料进入上下文；本体在完成、受阻或需要用户决定时发送消息。主 Session 串行处理当前输入与后台事件；未消费材料按 Session 回执和动作账本恢复。

停止整项工作时取消其全部子委派，指定停止某个帮手时仅取消该帮手。已有成果保留，不自动回滚已发生的操作。外部进程未确认终止时显示正在停止并继续占用相关资源；其他独立工作继续。取消意图与迟到结果需核对，不能因结果返回而自动复活已停止的工作。

## 执行权限模式（已确认）

默认采用受限模式：明确可读目录、可写目录、网络访问及有效期，范围内自主执行，越界申请扩展权限。支持用户为一次工作明确开启可信本机模式，允许较广泛的本机操作并减少逐次命令确认；如实说明其继承的权限，不将其描述为已强制限定于工作目录。

用户目标授权、执行环境权限、动作确认分别管理。删除原件、对外发送与扩大权限等需相应明确授权；目录写权限通常也能删除文件，禁止删除原件不能仅靠目录沙箱，应使用受控操作接口。Shell、MCP 与外部编码 Agent 各自落实边界，Shell 沙箱不会自动限制远端 MCP。

本轮保留统一权限接口并优先验证可复用的隔离后端，不以自研 Windows 沙箱为主要工程。没有隔离能力的后端明确标记为可信执行，只在用户授权该模式后使用；无法实现的限制不得静默放宽。默认受限 Shell 在无匹配后端时受阻；只有用户明确开启可信模式才继承 Host 权限。本机候选实测只有部分边界，仍不能执行完整受限命令。

## 自动召回触发（已确认）

自动背景召回仅在用户输入时触发。同一输入的工具续步和重启复用对应记录，后台结果续接不触发新的自动召回；需要更多背景时使用主动搜索。预算、去重和接口字段由实现方案给出默认值并验证，不重复作为产品选择询问。

产品方向和行为规则已确认，剩余工作是原生工具搜索适配、Windows 执行权限后端、委派恢复及旧数据兼容的技术核验；不再将已确定的规则列为待决定。首轮方案与实际证据见 [落地核验与改动计划](../personal-agent-refactor-plan.md)。

用户调用 to-spec 后已发布设计结论与实现规格，未再次访谈常规实现细节。运行时已在 development 按六项任务迁移，未验证的真实环境不能当作已通过证据；合并 main 仍需用户明确同意。

## 实现记录（2026-10-13）

Telegram 输出按用户后续确认的 #174 接入 Rich Markdown 正式消息和当前用户回复的正文草稿，调整 ADR-0007 历史 plain Telegram 选择。草稿仅为 Channel 临时预览，公开正文由 Pi 经 Host 通知，后台输出与工具参数不直接广播；正式 Delivery、消息关联、记忆学习和未知发送不重发保证继续保留。结构分页、格式降级及当前验证边界见 [输出说明](../personal-agent-operations.md#telegram-回复渲染与预览174)。

Host 以整体工作、独立子委派、WorkEvent 和动作账本为业务真相；Pi 主 Session 接回帮手材料，按最新要求继续整体目标。子完成不直接 Delivery。原生发现保持常驻前缀稳定，网页、plan_control、working_agreements 和连接器专用定义按需加载；普通端点明确缺失，通用文件/工作控制继续可用。

自动召回只由真实用户输入触发，持久 started/ready/unavailable/excluded 与呈现出处防止重启重复召回。孩子只接收本体选定原文/必要约定，额外背景请求是执行材料。工作约定通过独立修订事实及用户后续明确确认保存。

受限后端除能力外匹配执行身份、证据、当前范围；Shell/独立检查/herdr 在异步核对后重读权限，原始模式、目标或范围变化不能沿用旧授权。Codex unelevated candidate 当前仅注册诊断并拒绝派发，没有通用可执行沙箱实现。实际 OS/二进制和采样限制见本轮验收。

远端来源回执保存成功受控检索的 requested URL、provider-returned content、摘要、版本及 owner/root 身份，不声称提供独立 HTTP/freshness 核验。错误出处和伪造摘录保持 partial；本体仍判断结论是否符合目标。真实 SIGKILL 恢复用例与 throw/协议夹具分别列证据，真实 Anthropic 与本轮 Telegram 仍未验证；未部署或合并。
