# 分层记忆与稳定活动上下文分开维护

2026-10-17，[ADR-0015](0015-system-context-order-and-self-file.md)已将基础指令迁入环境配置，SELF 文件维护身份与关系，系统内容按稳定性排序。下文保留 2026-10-16 的实现与验收；SELF 权威来源及系统顺序以后续 ADR 和[当前操作说明](../personal-agent-operations.md)为准，生产服务是否切换另行核对。

设计结论：[Issue #207](https://github.com/CxHsin/nailong-bot/issues/207)。正式规格：[Issue #208](https://github.com/CxHsin/nailong-bot/issues/208)，见[本地规格归档](../research/context-management-spec-2026-10-16.md)。

2026-10-16，用户在 [上下文管理讨论](../research/context-management-decisions-2026-10-16.md) 中确认：长期记忆采用常驻 Markdown 档案、主题自动浮现和 Akasha 原文召回，保留主动搜索。允许有用户原话依据的稳定画像与关系理解，当前表达优先。该方向扩展 [ADR-0011](0011-durable-main-agent-and-conversation-queue.md) 留待后续的上下文与记忆范围。

system 记忆快照在同一压缩代内固定，持久保存以便重启复用；新记忆和纠正通过追加材料即时进入上下文。主助手统一写入共享记忆，helper 提交候选；压缩后从原始对话后台提炼，明确要求记住或忘记时立即处理。这样在允许记忆更新的同时避免每轮重写缓存前缀。遗忘优先于缓存，须使相关快照与摘要立即失效。

长工具结果保存为持久原件，活动上下文保留受限视图和可分页读取的引用。压缩保留近期对话原文，以及目标、约束、决策原因、进度和下一步的摘要，让模型理解已做什么、结果如何及是否还需继续；详细执行记录由 Durable 保存，摘要不要求逐工具列出元数据。保留继续或核查所需的来源定位信息，其余细节按需分页查询。先复用原生容量触发和后台压缩，空闲压缩收益另测。

已知引用直接分页读原件；引用不在摘要中时，通过固定入口检索 Durable 调用元数据及归档位置，返回有限候选，再读取选定页面。索引由程序维护，无需额外模型调用或完整常驻索引，也不另建执行流水。

为了保持主 agent 的上下文，高成本且会产生大量中间材料的独立子任务使用 helper 上下文，同一子任务复用同一 helper，回传推进整体目标所需的结果和必要来源。截图和批量图片是例子，委派不限于视觉任务；轻量工作由主助手直接处理。此选择控制主上下文增长，但是否降低总费用仍须用实际调用验证。

## 实现与验证

实现接入现有 Assistant Service 和 Pi Durable 1.2.0，工具原件、媒体 manifest、记忆与快照各自持久保存。SQLite 保存有来源和版本的记忆，Markdown 是可阅读的当前档案；当前 Akasha 采用本地词项及中文相邻双字匹配，不复用旧 Host 图内核。模型写入与压缩后的原文提炼共用来源、版本及遗忘校验，helper 仅回传候选。

遗忘/纠正沿来源关系使助手派生内容失效。受影响的压缩摘要从仍有效的原始材料和 Durable 工具记录定位重建并保存；后续原生压缩也使用清理后的材料。快照、自动召回和新追加材料的来源都纳入摘要范围，覆盖 reset 后通过长期记忆进入对话的事实。

稳定 section 顺序与原生压缩遵循 SDK 编码器；有遗忘材料时通过 beforeCompact 提供清理后的摘要，普通压缩继续走原生实现。真实模型验证了偏好、SELF、项目主题、纠正、遗忘、原生压缩续接，以及同一 helper 的大资料和图片分析。[验收记录](../context-management-acceptance-20261016.md)说明受控测试、真实用量、失败修复与证据范围；默认预算及配置见[操作说明](../personal-agent-operations.md)。
